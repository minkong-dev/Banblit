# 글쓰기 규칙

이 규칙의 목적은 하나다. **읽는 사람이 유추하지 않아도 되게 쓴다.** 줄이는 것도, 용어를 그대로 쓰는 것도, 한자어를 쓰는 것도 전부 그 목적을 위한 수단이다. 규칙끼리 부딪히면 "유추가 필요 없는가" 로 판단한다.

## 어투

| 대상 | 어투 | 이유 |
|---|---|---|
| 코드 주석, docstring, 문서(.cluedoc, dev_history, README) | 경어. 기본은 "~합니다" 체. 필요하면 "~할 수 있었는데요" 같은 "~요" 체와 도치법 | 사용자 이외의 다른 사람이 읽는 글이다 |
| 사용자에게 보내는 답변 | 사용자 선호 어투. 지금은 존댓말, 호칭은 "개발자님" | 읽는 사람이 정해져 있다 |

## 원칙

1. **내용은 보존하고 표현만 줄인다.** 원문의 조건·대상·결과 개수가 고친 뒤에도 같아야 한다. 줄이는 대상은 말투와 유추어뿐이다. 조건을 빼고 짧아진 것은 간결이 아니라 정보 삭제다.
2. **대상을 명시한다.** "시작과 끝" 이 아니라 "시작시간과 종료시간". 무엇의 시작인지 읽는 사람이 채우게 하지 않는다.
3. **결과는 값으로 적는다.** "가능하다" 가 아니라 "True 를 반환한다". "돌려준다" 가 아니라 "반환한다".
4. **조건은 조건문으로 적는다.** "~할 경우", "~하지 않으면". 조건을 빼고 결론만 남기지 않는다.
5. **한자어로 뜻을 고정한다.** 수정·삭제·추가·이동·반환·검증·충족·배정·출력·발생·미구현·잘못된. 보류·후행·선행·유예·착수. 고치기·지우기·앉히기·돌려주기·틀린·미루기·나중·먼저것 같은 말은 쓰지 않는다. 같은 동작은 어디서나 같은 단어다.
6. **영어 용어는 그대로 쓰고, 첫 등장에 정의를 괄호로 붙인다.** slot(1시간 단위 시간 칸), tzinfo(시간대 정보), polling(주기적으로 서버에 같은 요청을 다시 보내 변경을 확인하는 방식). 두 번째부터는 용어만 쓴다. 용어를 한글로 바꿔 쓰면 읽는 사람이 원래 용어를 거꾸로 추측해야 한다.
7. **직관적이지 않은 말을 쓰지 않는다.** 붙박이·걸치기·나눠쓰기·낭독기·되묻기·말풍선·통로 같은 비유와 조어 금지. 스크린 리더, refetch, 프로필 카드, endpoint 처럼 원래 용어로 쓴다.
8. **매개변수·상수·함수는 이름으로 부른다.** "필요한 개수" 가 아니라 `slots_per_team`. 코드와 주석이 같은 이름을 쓴다.
9. **이유는 실제로 일어나는 일로 적는다.** "조용히 틀린 답을 낸다" 가 아니라 "error 를 발생시키지 않고 잘못된 배정안을 출력한다". 비유 대신 결과.
10. **중복은 삭제한다.** docstring 에 적은 제약 조건을 아래 코드 주석에 다시 적지 않는다.
11. **같은 내용이면 짧은 쪽.** 10줄과 2줄의 내용과 전달력이 같을 때만 2줄이다.
12. **표가 유리하면 표.** 항목이 셋 이상이고 같은 축으로 비교될 때 표를 쓴다. 문장 하나짜리는 표로 만들지 않는다.
13. **결론이 먼저다.** 답변은 "무엇이 어떻게 바뀌는가" 한 문장으로 시작하고, 이유와 배경은 그 뒤에 붙인다.
14. **지칭은 명사로 한다.** "것·그것·이것·이 안·여기·남의 것" 같은 대명사로 대상을 가리키지 않는다. 앞 문장의 명사를 그대로 다시 쓴다. "다른 사용자의 것" 이 아니라 "다른 사용자의 일정".
15. **수량은 숫자와 단위로 쓴다.** "여럿·몇몇·많은·일부·하나둘" 같은 어림 표현을 쓰지 않는다. "같은 포지션이 여럿일 때" 가 아니라 "같은 포지션이 1명 이상일 때".
16. **제품 용어는 프로젝트가 정한 이름 하나만 쓴다.** 이전 이름, 상위어, 동의어, 순한글 변형으로 바꾸지 않는다. 용어가 바뀐 적이 있으면 새 이름만 쓴다. 이 PC 의 Banblit 프로젝트에서 정해진 것: 포지션(악기 ✗), 버튼(단추 ✗), 배정기록(회차 ✗ — 화면 문구는 "이전 배정기록"), 합주실(방·연습실 ✗), 수정·삭제·추가(고치기·지우기·앉히기 ✗), "<대상> 아이콘"(알림 벨 ✗).
17. **문장은 동작 하나를 말하고 끝낸다.** 뜻이 끝난 뒤에 되풀이·부연 문장을 붙이지 않는다. "예약 가능한 합주실을 표시합니다." 로 끝난다. "어디에 할지는 이 안에서 선택합니다" 같은 뒷문장은 삭제한다.
18. **의인화·비유로 동작을 설명하지 않는다.** "화면이 값을 지어낸다", "서버가 조용히 틀린 답을 낸다" 같은 표현 금지. 실제로 일어나는 동작을 주어와 목적어로 적는다: "화면은 서버에서 받은 값만 표시합니다".
19. **무엇인지만 적고 생김새는 적지 않는다.** 아이콘·그림·색의 모양이나 구성("흔들리는 몸통과 추 두 획")을 설명하지 않는다. "알림 아이콘입니다." 로 끝난다.

## 적용 예

| 전 | 후 | 규칙 |
|---|---|---|
| 슬롯이 멤버의 불가능 시간 어느 하나와도 겹치지 않으면 가능. | slot(1시간 단위 시간 칸)이 멤버의 불가능 시간 중 어느 하나와도 겹치지 않을 경우 True 를 반환합니다. | 3·4·6 |
| 조건을 모두 만족하는 배정을 찾지 못하면 feasible=False로 돌려준다. | 조건을 모두 충족하는 배정안이 없을 경우 feasible=False 를 반환합니다. | 1·4·5 |
| 시작과 끝이 있는 시간 구간. 잘못된 구간을 만들 수 없게 막는다. 여기서 걸러내지 못하면 엔진이 뒤에서 조용히 틀린 답을 낸다. | 시작시간과 종료시간이 있는 시간 구간입니다. 생성 시 검증합니다. 여기서 검증하지 않으면 엔진이 error 를 발생시키지 않고 잘못된 배정안을 출력합니다. | 2·5·9 |
| tzinfo 가 붙은 시각은 거부한다. 시간대 지원은 아직 열지 않았다. | tzinfo(시간대 정보)가 있는 datetime 은 거부합니다. 시간대 지원은 미구현입니다. | 5·6·7 |
| 낭독기가 듣는 이름과 눈으로 보는 이름이 같아야 한다. | 스크린 리더가 읽는 이름과 화면에 표시되는 이름이 같아야 합니다. | 5·7 |
| 내가 등록한 못 나오는 시간 하나를 지운다. 남의 것은 서버가 없는 것과 같게 거절한다. | 자신이 등록한 불가능 일정 하나를 삭제합니다. 다른 사용자의 일정은 서버가 없는 일정과 같게 거절합니다. | 5·14·16 |
| 같은 악기가 여럿일 때 몇 번째인지. 화면은 "일렉 2" 처럼 붙여 보여준다. | 같은 포지션이 1명 이상일 때, "일렉 2" 처럼 포지션에 숫자를 부여해 표시합니다. | 15·16 |
| 저장이 끝나면 그 목록을 다시 받아온다. 화면이 스스로 값을 지어내지 않게 한다. | 저장이 끝나면 목록을 서버에서 다시 조회합니다. 화면은 서버에서 받은 값만 표시합니다. | 18 |
| 예약을 넣을 수 있는 합주실 전부. 어디에 넣을지는 이 안에서 고른다. | 예약 가능한 합주실을 표시합니다. | 17 |
| 알림 종. 흔들리는 몸통과 아래 추 두 획으로 그린다. | 알림 아이콘입니다. | 16·19 |
| 사이드바를 열고 닫는 단추와 로고 | 사이드바를 열고 닫는 버튼과 로고 | 16 |
| 이 항목은 나중에 미룬다. 나중 저장이 앞선 수정을 덮어쓴다. | 이 항목은 보류합니다. 후행 저장 요청이 선행 수정 내용을 덮어씁니다. | 5·14 |

틀린 방향의 예. "시작·끝이 있는 시간 구간. 생성 시 검증한다." 는 짧아졌지만 무엇의 시작인지, 무엇을 검증하는지가 빠졌다. 규칙 1·2 위반이다.

## 보내기 전 점검

작성 후 다음의 조건을 검토한다.

- 영어 용어를 한글 비유나 조어로 바꿔 쓴 자리가 있는가. 있으면 원래 용어로 되돌리고 첫 등장에 정의를 붙인다.
- 원문보다 조건·대상·결과가 줄었는가. 줄었으면 되살린다.
- "가능·잘못된·필요한·적절한" 처럼 읽는 사람이 채워야 하는 말이 남았는가. 남았으면 값·조건·이름으로 바꾼다.
- 적절한 레퍼런스를 참고하였는가. 성공적인 사례를 확인하지 않았다면 확인 후 답변 및 작성을 진행한다.

## 적용 범위 밖

화면에 표시되는 문구(버튼, 안내문, 오류 문구)는 이 규칙이 아니라 사용자가 직접 정한 제품 용어를 따른다. 동작 이름은 수정·삭제·추가로 고정되어 있다.
