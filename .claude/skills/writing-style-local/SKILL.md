# Banblit 글쓰기 보충

전역 `writing-style` 스킬의 규칙 위에 이 저장소에서 확정된 표기만 적습니다. 아래 표기는 다시 묻지 않고 적용하고,
저장소의 옛 주석, 문구가 다른 표기를 써도 따라 쓰지 않습니다. 2026-10-07 에 개발자님이 확정했습니다.

## 확정 표기 (다시 묻지 않는다)

| 쓰는 이름 | 쓰지 않는 이름 | 비고 |
|---|---|---|
| 집중 합주기간 | 집중합주 기간, 집중기간 | 띄어쓰기 고정 |
| 전체 합주 | 전체합주 | 띄어쓰기 고정. 옛 코드, 문서에 "전체합주" 가 남아 있어도 새 글은 "전체 합주" |
| 팀별 합주 | 팀별합주 | 띄어쓰기 고정 |
| 공연명 | 기간 이름 | `periods.name` |
| 합주실, 합주실명 | 방, 연습실, 합주실 이름 | |
| 포지션 | 악기 | |
| 배정기록 | 회차 | 화면 문구는 "이전 배정기록" |
| 권한 세트 | 권한 묶음 | |
| 불가능 일정 | 불가능 시간 | 서버 열 이름이 `unavailable` 이어도 글은 "불가능 일정" |
| 시작 시간 / 종료 시간 | 시작 시각, 끝 시각, 시작, 끝 | 시간 입력 라벨, 검증 문구 전부. 여러 번 지적받음 |
| 버튼 | 단추 | |
| "<대상> 아이콘" | 벨, 종 | 모양은 적지 않음 |
| 시각 표기 | 칸 | 화면에서 "칸" 을 쓰지 않음. 칸(slot)은 계산 엔진의 단위 |
| 존재하지 않는 X입니다, X가 존재하지 않습니다 | 그런 X이 없습니다, X가 없습니다 | 없는 대상을 조회한 오류 문구, 대상의 부재를 말하는 모든 문장 |
| 테스트 도구(pytest, mypy, vitest, lint) | 검사 도구 | 도구는 이름이나 "테스트 도구" 로 부름. "검사" 는 동작(타입 검사, 입력 검증)에만 씀 |
| 존재하지 않는 명령어입니다, 존재하지 않는 switch 입니다 | 모르는 명령입니다 | 입력값이 목록에 없을 때의 오류 문구 |
| 백업을 진행합니다, 백업을 생성합니다 | 백업 1벌, 한 벌 떠 둔다 | "벌" 단위를 쓰지 않음. 횟수가 필요하면 "1회" |
| 수정, 삭제, 추가, 변경, 선택, 해제, 설정, 지정, 배치, 반려 | 고치기, 지우기, 넣기, 바꾸기, 고르기, 비우기, 정하기, 서다 | 동작은 한자어 + 하다/됩니다. 답변, 주석, 문서, 화면 전부 |
| 공백, 쉼표, 마침표 | 가운뎃점(, ) | 값 사이는 공백, 단어 나열은 쉼표, 문장 이어붙임은 마침표 |
| Docker image | image, 이미지(container 뜻일 때) | container 의 image 는 항상 "Docker image". "이미지" 는 그림 파일(미리보기 이미지, og:image)에만 씀. 2026-10-08 지적 |
| `stage 에서`, `image 를`, `.env 가` | `stage에서`, `image를` | 영어 단어, 파일명, 코드 이름 뒤의 조사는 공백 1개를 두고 붙임. banblit.sh 전체가 이 표기 |
| Merge 커밋, Revert 커밋 | 병합 커밋, 되돌리기 커밋 | git 이 생성하는 커밋 종류는 git 용어 그대로 |
| 초기화합니다 | 비우고, 지웁니다 | DB, 폴더의 내용을 전부 삭제하고 처음 상태로 되돌리는 동작 |
| 캡처 | 캡쳐 | 표준 표기 |
| 쉼표, "순서" | 화살표(→) | "caddy, web(nginx), api 순서". 주석, 문서, 답변 전부. 코드 블록 안 명령 예시는 예외 |

## 제품 이름

- 서비스 이름은 `Banblit`(코드, 문서), 화면 로고는 `banblit`(CI 심볼). 한글로 바꿔 쓰지 않습니다.
- 제품 용어는 그대로 둡니다 — 합주실, 기간, 집중 합주기간, 전체 합주, 팀별 합주, 배정, 조율안, 소속, 포지션, 공지사항, 팀 게시판, 불가능 일정, 예약, 반려, 블라인드, 스케줄링.

## 분야 용어 (원문 그대로 + 첫 등장에 정의)

slot(1시간 단위 시간 칸), endpoint, session, cookie, refetch, polling, dialog, modal, toast, rail(본문 오른쪽 칸), migration,
transaction, grid, CP-SAT, OR-Tools, 스크린 리더, aria-label, 포커스. 한글 비유(낭독기, 되묻기, 통로, 날짜 창, 껍데기)로 바꾸지 않습니다.

자동화 파일(banblit.sh, compose, Dockerfile, nginx, Caddyfile)의 용어도 원문 그대로입니다 — Docker image, container, service, stage(Dockerfile 의 FROM … AS 단위),
layer, cache, volume, host, profile, anchor(compose 의 `x-*: &이름`), entrypoint, envsubst, DNS resolver, content hash, build arg, reverse proxy, override,
revision(alembic), pg_dump, 테스트 도구. stage 는 이름으로 부릅니다(base, dev, prod). service 도 이름으로 부릅니다(api, web, db, dev, backup, caddy).

## 문서별 고유 규칙

| 문서 | 규칙 |
|---|---|
| 개발일지 `dev_history/YYYY-MM-DD.md` | 맨 앞 "지금 상태"(무엇을 하던 중, 어느 파일이 어떤 상태, 다음 한 걸음), "용어" 표(`\| 말 \| 뜻 \|`), 트러블슈팅은 무엇이, 왜, 어떻게, 맨 끝 "남은 것". 커밋 목록은 적지 않음 |
| `.cluedoc/<폴더>/<폴더>.md`(루트는 `Banblit.md`) | 문서 버전 `x.y.z draft`, "어떻게 확인했나" 절에 테스트 파일 경로, 시나리오, 실행 명령. 사용자 결정은 날짜와 함께. paper 사이 링크는 Obsidian wikilink `[[경로/README#절\|표시 글]]`(vault 루트 `.cluedoc/`). 상대 경로 markdown 링크를 쓰지 않음(2026-10-08 결정) |
| `COMMAND.md` | 실행해 확인한 명령만. 실행 경로, 용도, 옵션 전부의 뜻(생략 시 기본값), 주의점 |
| 화면 문구 | 안내문은 "~해요" 체("가입한 멤버의 목록이에요"). 동작 버튼은 한자어 명사형("저장", "삭제", "반려", "글쓰기"). placeholder 는 "~을 입력해주세요." |
| 코드 주석 | "~합니다" 체. 사용자 결정은 "(사용자 결정 YYYY-MM-DD)" 로 표시 |
| 자동화 파일 머리 주석 | 1줄째는 무엇을 하는 파일인지("배포용 nginx 설정입니다"). 호출 방법이 있으면 인자마다 1줄("인자 없음: …", "once <파일이름>: …"). 어느 파일이 이 파일을 실행하는지 1줄("docker-compose.yml 의 backup service 가 실행합니다"). 경위, 사례, 날짜는 적지 않음 |
| 터미널 안내 문구(step, note, fail) | banblit.sh 에 개발자님이 직접 쓴 문장이 기준. "~합니다", "~하십시오", "~해주십시오". 없는 대상은 "존재하지 않습니다", 찾기 실패는 "찾지 못했습니다", 시간 초과는 "응답 시간이 초과되었습니다. N초 이내에 응답하여야합니다" |
