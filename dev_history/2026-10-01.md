## 트러블슈팅

### J7 — 의도된 제외를 불일치로 판정함

- **무엇이**: `ACCEPTED_MIME` 에 `audio/flac` 를 추가했다가 되돌렸습니다.
- **왜**: 서버 `INLINE_TYPES` 에 flac 이 있고 화면 목록에 없는 것을 불일치로 판정했습니다. `lib/richText.ts:160` 에 "flac 은 Safari 가 열지 못해 넣지 않습니다" 라는 제외 사유가 이미 있었고, 본문 삽입 판정은 `ACCEPTED_MIME` 이 아니라 `embedKind` 였습니다. 목록 두 개만 비교하고 그 목록을 쓰는 코드를 읽지 않았습니다.
- **어떻게**: `react-reviewer` 가 지적해 되돌렸습니다. 목록 세 곳(입력 필터·삽입 판정·서버 inline)의 역할과 정본 위치를 각 주석에 적었습니다. 두 목록이 다를 때는 그 목록을 읽는 코드와 주변 주석을 먼저 확인합니다.

### `python -` heredoc 이 셸을 120초 멈춤 — 세 번째

- **무엇이**: 줄 수를 세는 명령 안에 빈 `python - <<'PY'` 를 넣어 셸이 멈췄습니다.
- **왜**: 9/30 개발일지에 두 번 적힌 문제(이 PC 의 `python` 은 Windows Store 안내 stub)를 반복했습니다.
- **어떻게**: 백그라운드로 넘어간 작업을 중단하고 `grep -n` 결과의 줄 번호 차이로 셌습니다. 이후 에이전트 지시문 전부에 "호스트에서 python 을 실행하지 않습니다" 를 넣었습니다.

### lint 가 사유 보관 방식 두 가지를 거절함

- **무엇이**: 안내 문구의 사유를 보관하려고 렌더 중 `useRef` 수정, `useEffect` 안 `setState` 를 차례로 썼고 둘 다 `npm run lint` 가 거절했습니다(`Cannot access refs during render`, `Calling setState synchronously within an effect`).
- **어떻게**: 렌더 중 조건부 `setState`(`if (failedWhy !== "" && failedWhy !== meWhy) setMeWhy(failedWhy)`)로 바꿨습니다. React 문서의 "렌더 중 state 조정" 방식이고 lint 를 통과합니다.

### `sed` 로 블록을 교체하다 줄을 잘못 삭제함(2회)

- **무엇이**: `ACCEPTED_MIME` 교체에서 닫는 `];` 가 2개 남았고, `retryMe` 추가에서 함수의 닫는 `}` 자리에 다른 줄이 들어갔습니다.
- **왜**: 교체 범위의 끝 줄 번호를 확인하지 않고 `tail -n +N` 을 계산했습니다.
- **어떻게**: 교체 직후 `sed -n` 으로 경계를 출력해 발견하고 수정했습니다. 타입 검사 전에 잡혔습니다.
