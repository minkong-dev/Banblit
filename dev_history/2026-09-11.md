# 2026-09-11 — 화면 문구를 사용자가 직접 정리했고, 다음 할 일 열세 개를 코드와 대조했다

## 지금 상태

**코드는 하나도 안 고쳤다.** 오늘은 사용자가 화면에 나가는 문구를 직접 다 고쳤고(`frontend/src/lib`
다섯 파일, `Landing.tsx`, `Assignment.tsx` 주석 한 줄), 그에 맞춰 옛 문장을 단언하던 테스트만
새 문구로 바꿨다. 화면 테스트 221개 통과, tsc 0개.

`TEXT.md` 는 15·16절만 남기고 잘라냈다. 남은 것은 "코드와 문구가 안 맞는 곳" 목록이라 곧 할 일이다.

**다음 한 걸음은 아래 "남은 것" 1번 묶음이다** — 결정이 필요 없는 것부터. 시작 전에 이 파일의
"결정된 것" 을 읽는다. 사용자가 오늘 결정한 것이 다섯 개 있고, 그것을 모르고 손대면 방향이 어긋난다.

### 결정된 것

**3번 — 헤드매니저.** 고정 계정을 두지 않는다. 두 가지를 한다.

- 역할 글자를 "헤드매니저" 대신 **가진 권한 묶음의 이름**으로 보여준다. 첫 묶음 이름을 바꾸면
  표시도 따라간다. 전부 켜진 묶음이 여러 개면 각자 제 이름이다.
- **항목이 전부 켜진 묶음이 하나뿐이면** 그 묶음의 삭제와 항목 끄기를 서버가 거부한다.
  사람 기준이 아니라 **묶음 기준**이다. 사람에게서 떼는 것은 막지 않는다.

**5번 — 매일.** 체크박스가 켜지면 **끝나는 날 없이 매일이 집중 합주기간**이다. 정해진 계산 시각마다
자동 배정이 계속 돈다. 이 뜻을 되묻지 않는다 — 사용자가 세 번 말했다.

**8번 — 탈퇴시키기.** 권한 항목을 하나 새로 만든다. 이름은 **"멤버 추방"**. 설정의 멤버 탭에 단추를
붙인다. 추방하면 팀 자리는 비고 글·예약은 남는다.

**11번 — 설정 탭.**
- 멤버 탭에 "멤버 추방" 단추 (멤버 추방 권한자에게만)
- **예약 탭 신설** — 모든 멤버의 예약 목록과 취소 단추 (타 멤버 예약 수정 및 취소 권한자에게만)
- 게시판 관리는 탭을 만들지 않는다. 권한 항목 "타 멤버 글 수정 및 삭제"가 이미 있으므로
  글·댓글·첨부 옆 삭제 단추가 그 권한자에게도 보이게만 한다

**12번 — 알림.** 일단 넘긴다.

### 트러블슈팅

- **테스트가 옛 문구를 단언하고 있었다.** 사용자가 `lib` 다섯 파일의 문구를 고쳤는데 테스트는
  그대로라 1개가 깨졌다(`settings.test.ts` "닫는 시각은 여는 시각보다 늦어야 합니다"). 테스트
  다섯 파일에서 옛 문장 열네 개를 새 문장으로 바꿨다. 문구는 사용자가 고른 것이니 테스트를 따라
  맞춘 것이 맞다.
- **기수 상한이 화면과 서버가 다르다.** 사용자가 화면을 200→100 으로 바꿨는데 서버
  `input.py:18` 의 `MAX_COHORT` 는 200 이다. 아직 안 맞췄다 — 남은 것 1번에 있다.
- `.gitignore` 에서 `docs/`·`.superpowers/` 제외를 지웠다. 디스크에 그 폴더가 없어 지금은 영향 없다.
