# 2026-08-28 — 배정 계산의 비용을 재고, 리팩토링을 끝냈습니다

## 먼저 물은 것: 이 계산이 얼마나 걸리나

어제 만든 `refactor-audit`으로 위반 28개를 세어 둔 상태였습니다. 수정하기 전에 다른 문제가
있었습니다. 배정 계산의 비용을 아무도 모른다는 점입니다.

제 생각은 이랬습니다. 한 달은 길어야 31일이고 자리는 30분 칸으로 고정이니, 전체 칸 수가
정해져 있습니다. 그러면 최악의 경우도 계산할 수 있어야 합니다.

구체적으로 조건을 고정했습니다. 집중기간 14일, 10시~22시 개방, 합주실 1개, 팀 10개,
팀 최대 8명. 총 336칸입니다.

### 측정했습니다

컨테이너에서 실제로 돌렸습니다.

| 상황 | 걸린 시간 |
| --- | --- |
| 보통의 성공하는 배정 | 0.27 ~ 0.35초 |
| 한 사람이 3일 내내 불가능한, 제약이 겹치는 경우 | 8.69초 |
| 위 경우에서 조율안까지 만드는 전체 흐름 | 22.20초 |

세 번째 값이 답이었습니다. 조율안은 "한 명씩 빼 보고 풀리는지 확인"하는 방식이라,
사람 수만큼 계산을 반복합니다. 80명이면 80번입니다. **비용은 한 번 푸는 시간 × 사람 수**로
정확히 예측됩니다.

### 시간 상한은 넣지 않기로 했습니다

풀이에 제한 시간을 두자는 제안이 나왔는데 거절했습니다. 시간 상한은 답을 찾을 가능성을 버리는
선택입니다. 시간이 다 됐다고 "답이 없다"고 답하면, 실제로는 있는 답을 못 찾은 것인데
멀쩡한 사람을 빼라는 조율안이 나갑니다.

제가 원하는 것은 다음과 같습니다. **답을 하나도 버리지 않으면서, 걸리는 시간이 미리 정해져
있는 방식.**

지금 구조로도 그 방식이 가능하다는 것이 실측에서 드러났습니다. 실제 문제는 느린 것이 아니라,
계산이 실행되는 동안 서버의 worker 1개를 통째로 점유한다는 점입니다. 배정은 하루
2번 실행되는 일괄 작업이니, 계산을 서버 밖으로 분리하는 것이 맞습니다. 시간 상한이나 greedy 알고리즘으로
교체하는 것은 답이 아닙니다.

## 리팩토링 — 28개 중 16개를 수정했습니다

성능 결론이 "구조를 바꿀 일"로 정리됐으니, 먼저 리팩토링을 마쳤습니다.

수정한 것을 하나씩 다시 확인했습니다. 한꺼번에 보고받으면 무엇이 왜 바뀌었는지 남지
않기 때문입니다. 그 과정에서 4가지를 새로 정했습니다.

### 엔진이 이름 대신 번호를 씁니다

가장 큰 결정입니다. 계산 엔진이 합주실과 사람을 문자열로 구분하고 있었습니다.

```
"1번방 (2026-08-01)"   ← 합주실 이름 + 날짜를 붙여 만든 문자열
"김민수 #7"             ← 이름 + 사람 번호를 붙여 만든 문자열
```

이 구조를 보고 이상하다고 생각했습니다. 데이터베이스는 이미 합주실 번호와 시작 시각으로 자리를
구분하고 있는데, 계산에 넘길 때만 문자열로 합쳤다가 돌아올 때 다시 분리하고 있었습니다.
문자열이 달라도 검증할 방법이 없고, 저장 형식을 강제할 수도 없습니다.

사람 쪽도 마찬가지로 물었습니다. 동명이인이 있으면 이름으로는 구분하지 못합니다. 이름이 같고
정보도 같으면 오히려 분리하면 안 됩니다. 그러면 사람 table의 기본키를 그대로 사용하는 것이 맞습니다.

결정: **엔진은 번호만 받습니다. 이름은 엔진 밖에서만 씁니다.** 자리 하나는 합주실 번호와 시작
시각 값 2개가 가리킵니다. 변환할 대응표 3개가 전부 삭제되었습니다.

추가로 검증이 강화되었습니다. 전에는 "합주실 이름이 겹치나"만 봤는데, 이제 "같은 합주실의 같은 칸이
2번 세어지나"를 봅니다. 이름이 달라도 운영시간이 겹치면 검출됩니다.

### 검사를 폴더로 구분합니다

DB가 있어야 실행되는 검사를 선택하는 방법이 `-m "not db"`였습니다. 사용자가 좋지 않은 방식이라고 했습니다. 그리고
외부와 통신해야 하는 대상이 DB만은 아닙니다. LLM도 있고 메시지 브로커도 올 것입니다.

결정: `tests/unit`과 `tests/integration/<의존 대상>/`으로 나눕니다. 폴더 이름이 곧 표시
이름입니다. 나중에 `integration/llm`을 만들면 표시가 저절로 붙습니다.

### 저장소에 닿지 못했을 때

DB가 끊기면 503으로 답하기로 했는데, 그러면 화면이 무엇을 할지가 남았습니다. 자동으로 다시
보내면 이미 응답하지 못하는 저장소에 요청이 반복해서 몰립니다.

결정: **화면에 재시도 버튼을 만듭니다.** 다시 보낼지는 사람이 정합니다.

### 타입 검사기를 넣습니다

`AssignmentRow`로 항목 이름을 한 곳에만 적도록 정리했다고 보고받았는데, "그러면 이름을
잘못 쓰면 실행 전에 검출되나"를 물었더니 아니었습니다. 검사기가 아예 없어서 편집기만
표시해 줄 뿐이었습니다. `CLAUDE.md`가 모든 함수에 타입 표기를 요구하는데 그 요구를 확인하는
도구가 없었던 셈입니다.

결정: mypy를 넣습니다.

## 트러블슈팅

### 1. 서버 컨테이너가 DB 주소를 아예 갖고 있지 않았습니다

- **언제**: 리팩토링 뒤 검사 139개가 모두 통과한 상태에서, 규칙대로 실제로 실행해 확인하던 중
- **어디서**: `docker-compose.yml`의 `api` 서비스
- **무엇이**: `/periods/1/schedule`이 500을 냈습니다. `DATABASE_URL 환경변수가 설정되지 않았습니다`
- **왜**: `dev` 서비스에만 환경변수가 있었고 실제로 서버를 실행하는 `api`에는 없었습니다.
  **DB를 쓰는 화면 기능이 전부 동작하지 않았습니다.** 검사는 자기가 직접 접속 주소를 만들어
  쓰므로 `api`의 설정을 한 번도 거치지 않습니다. 검사가 전부 통과해도 배포 설정의
  오류는 검출되지 않습니다
- **어떻게**: `api`에도 같은 주소를 주고, `db`가 정상이 된 뒤에 기동하도록 순서를 지정했습니다
- **남는 영향**: 없습니다. 다만 "검사 통과 = 동작"이 아니라는 것이 확인됐습니다. 모듈을 나눈
  직후 실제로 실행해 보라는 리팩토링 규칙이 실제로 효과가 있었습니다

### 2. 저장 확정을 옮겼더니 검사 2개가 실패했습니다

- **언제**: 확정 책임을 저장 계층 안으로 모으는 항목을 수정한 직후
- **어디서**: 배정 저장과 되돌리기
- **무엇이**: 합주실·시각 충돌이 사용자 오류가 아니라 서버 오류로 반환되었습니다
- **왜**: 충돌이 확정 시점이 아니라 그 앞의 조회 시점에 발생하고 있었습니다. 원래 코드는
  쓰기와 확정을 하나로 감싸고 있어서 우연히 검출되었던 것입니다
- **어떻게**: 쓰는 부분 전체를 감싸고 확정은 그 뒤에 호출하도록 수정했습니다
- **남는 영향**: 없습니다

### 3. 마이그레이션 설정이 기존 logger를 전부 비활성화하고 있었습니다

- **언제**: 검사를 `unit`·`integration` 폴더로 나눈 직후, 전체를 실행했을 때
- **어디서**: 마이그레이션 설정을 읽어 들이는 부분
- **무엇이**: 기록에 남는지 확인하는 검사 1개가 실패했습니다. 단독으로 실행하면 통과하는데
  통합 검사 뒤에 실행하면 실패했습니다
- **왜**: 마이그레이션 설정을 읽는 함수가 기본값으로 **이미 만들어져 있던 logger(기록을 남기는 객체)를
  전부 비활성화합니다.** 마이그레이션을 실행한 뒤로는 서버가 아무것도 기록하지 못합니다.
  전에는 파일 이름 순서 덕에 이 검사가 먼저 실행되어 드러나지 않았습니다
- **어떻게**: 기존 logger를 비활성화하지 않도록 1줄 수정했습니다
- **남는 영향**: 사고가 났을 때 원인을 찾을 기록이 이제 실제로 남습니다. 폴더를 나눈
  덕에 드러난 것이라, 순서에 의존하던 검사가 1개 줄었습니다

### 4. 타입 검사가 예상보다 훨씬 조용했습니다

- **언제**: mypy를 처음 실행했을 때
- **무엇이**: 오류가 수백 개 날 것으로 예상했는데 17개였고, 전부 검사 파일이었습니다
- **왜**: 기본 설정은 **타입 표기가 없는 함수의 본문을 검사하지 않습니다.** 조용한
  것이 아니라 안 보고 있었던 것입니다
- **어떻게**: 표기가 빠진 것 자체를 오류로 검출하도록 설정했습니다. 39개가 더 나왔고, 그중 1개는
  소스의 실제 누락이었습니다(칸 격자를 확인하는 함수의 매개변수에 표기가 없었습니다)
- **남는 영향**: 없습니다. 소스 44개 파일이 오류 없이 통과합니다

## 오늘 확정된 것

- 배정 계산의 비용은 **한 번 푸는 시간 × 사람 수**로 예측됩니다. 측정했고 값이 있습니다
- 시간 상한은 넣지 않습니다. 답을 버리는 선택입니다
- 계산은 서버 밖으로 분리합니다(미구현)
- 엔진은 번호만 다룹니다. 이름은 엔진 밖에서만 사용합니다
- 검사는 `tests/unit` / `tests/integration/<의존 대상>/` 으로 나눕니다
- 저장소가 끊기면 503, 화면은 재시도 버튼을 표시합니다
- 타입 검사기는 mypy, 표기 누락도 오류로 검출합니다

## 남은 것

- **계산을 서버 밖으로 분리하기.** 배정을 비동기로 변경할지(요청 → 작업번호 → 조회) 먼저
  정해야 합니다. 이 결정이 나지 않아 `AUDIT.md`의 관련 항목 4개가 대기 중입니다
- **같은 사람이 2줄로 들어가는 것 차단.** 지금은 아무것도 차단하지 않습니다. 2줄이 되면
  그 사람의 불가능시간이 분리되어, 계산이 같은 시간에 2곳에 배정할 수 있습니다.
  계정 로그인에 걸려 있습니다
- **팀 이름이 겹칠 때.** 응답이 팀 이름으로 결과를 묶습니다. 저장소에 이름이 같은 팀이
  2개 있으면 한 팀의 시간표가 오류 메시지 없이 사라집니다. `/assign`은 차단했지만 기간 배정은 아직입니다
- **화면.** 아직 코드가 하나도 없습니다
- 저장소 루트의 `.claudesettings.local.json` — 경로를 잘못 써서 생긴 파일입니다.
  지금 상태로는 아무 효과가 없습니다
