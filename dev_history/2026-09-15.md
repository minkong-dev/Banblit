### 모달을 3단으로 다시 만들었습니다

`모달개선예시.png` 대로 왼쪽 타임라인, 가운데 폼, 오른쪽 내 일정 목록입니다. 색·글꼴은 기존 토큰을 그대로 썼고 배치만 새로 잡았습니다. 처음에는 카드 하나 안에 3열을 넣었는데, 사용자가 **"모달은 1개의 세트지만 각 부분이 분리된 것처럼 보이게"** 하라고 해서 `Modal` 에 `panes` prop 을 추가했습니다. 그 모드에서는 dialog 가 투명한 grid 틀만 되고, 카드(`.pane`) 3장이 각자 배경·모서리·그림자를 가집니다. 제목·닫기는 왼쪽 카드, 등록 버튼은 가운데 카드 안입니다. 이어서 **"일정이 없어도 카드 높이를 같게 맞추고, 넘치면 그 카드만 스크롤"** 하라고 해서 dialog 높이를 92vh 로 고정하고 grid 가 카드를 그 높이로 늘리게 했습니다. 폭도 3장 모두 같게(`repeat(3, minmax(0, 1fr))`) 맞췄고, 가운데 카드의 입력칸이 잘린다고 해서 처음에는 dialog 폭을 1320px 로 넓혔는데, 사용자가 "텍스트 필드 자체 문제 아니냐"고 되물어 1366×768 로 재현해 보니 **폭이 아니라 높이** 문제였습니다. 폼이 카드보다 길어 안쪽이 스크롤되고 그 경계가 사유 textarea 를 가로질러 잘린 것처럼 보였습니다. 폼 세로 간격과 textarea 최소 높이를 줄여 768px 높이에서 스크롤 없이 들어가게 했습니다(593/593px). 그래도 `텍스트필드.png` 처럼 **입력칸의 포커스 테두리가 양옆에서 잘렸는데**, 세로 스크롤 영역(`.col`)은 가로로 넘친 것도 잘라내고 카드 여백이 그 바깥에 있어 테두리 3px 가 들어갈 자리가 없던 것이 원인입니다. 좌우 여백을 스크롤 영역 안쪽으로 옮겼습니다(`.mbody` 와 같은 구조). 드롭다운 화살표는 브라우저 기본 화살표라 오른쪽 끝에 붙어 있어 SVG 로 직접 그려 오른쪽 16px 안쪽에 두었습니다. 타임라인 막대(선택 막대 포함)가 왼쪽 시각 글씨 칸을 덮고 있어 `.tl` 에 `--gutter`(50px)를 두고 막대의 `left` 를 그만큼 띄웠습니다(`모달 현재.png` 의 빨간 사각형 자리). 960px 이하에서는 카드가 세로로 쌓입니다.

- **드래그 선택**은 `DayTimeline` 이 pointer 이벤트로 받고, 순수 계산 `dragRange`(`lib/calendar.ts`)가 설정 단위로 내림해 구간을 만듭니다. 시작·끝 select 는 그대로 두었습니다 — 드래그와 같은 값을 바꾸며, 키보드 사용자의 입력 수단입니다

- 반복은 버튼 2개 → 드롭다운 1개(반복 없음·매일·매주 목요일마다), 예약자 선택 버튼 → "일정 이름" 드롭다운(내 팀 중 하나, 기본은 예약자 이름)

### 사이드바로 공지사항·팀 게시판에 가면 프로필 카드가 열렸다 닫혔습니다

코드만 봐서는 원인이 보이지 않았습니다(lazy 로딩 없음, `.pop` 정의는 `shell.css` 한 곳). 브라우저에서 사이드바를 누르는 순간부터 프레임마다 프로필 카드의 opacity 를 기록했더니, 새 화면의 첫 프레임에 opacity 1 로 계산되고 곧바로 0 으로 전환 애니메이션이 돌았습니다.

원인은 effect 실행 순서입니다. 화면을 옮기면 React 는 이전 화면의 cleanup(`body[data-shell]` 삭제)을 먼저 실행하고, 새 화면의 useEffect 는 자식부터 실행합니다. 공지사항·팀 게시판·팀 찾기에 있는 `useFitCount` 가 그 사이에 크기를 재면서 스타일 계산을 강제했고, 그 순간 `data-shell` 이 없어 `shell.css` 의 `.pop { opacity: 0 }` 이 적용되지 않았습니다. 부모인 AppShell 의 effect 가 속성을 되돌리자 opacity 가 1→0 으로 전환되었습니다. 대시보드·설정은 effect 안에서 크기를 재지 않아 증상이 없었습니다.

`AppShell` 의 `data-shell` 과 `usePage` 의 `data-page` 를 `useLayoutEffect` 로 바꿨습니다. 같은 기록으로 대시보드→공지사항, 공지사항→팀 게시판, 팀 게시판→팀 찾기 모두 opacity 최대값 0, 전환 0건을 확인했습니다.

## 트러블슈팅

- **배포 스크립트가 서버에서 세 번 연달아 터졌습니다.** (1) git 이 실행 권한 없이 올려서
  permission denied — `git update-index --chmod=+x` 로 해결. (2) 백업을 host 에서 뜨려다
  `/srv/banblit/backups` 가 root 소유라 거절 — `backup` 컨테이너를 빌려 그 안에서 뜨도록
  변경. (3) 백업 실패 검사가 파이프의 exit code 를 보고 있었는데 그 exit code 는 `gzip` 의 것이라
  `pg_dump` 가 죽어도 성공으로 읽혔습니다. `banblit.sh` 는 bash 라 `pipefail` 이 있어
  해결됐습니다.
- **배포 후 `/api` 가 전부 502 였습니다.** nginx 가 `proxy_pass` 에 적힌 이름을 기동할 때
  한 번만 풀고 그 주소를 영원히 씁니다. `api` 컨테이너만 다시 뜨면 IP 가 바뀌는데 nginx 는
  옛 주소로 계속 찔렀습니다. 주소를 변수에 담아 요청마다 다시 풀게 수정했는데, **`set` 이
  `rewrite` 와 같은 모듈이라 `break` 뒤에 두면 실행되지 않아** 빈 값이 들어가 이번엔 500 이
  났습니다. `set` 을 `rewrite` 위로 올려 해결했습니다.
- **임시 마이그레이션이 권한 마이그레이션 테스트를 깨뜨렸습니다.** `AFTER = "head"` 로
  끝까지 올리는 테스트인데, 가입한 적 없는 멤버를 삭제하는 임시 마이그레이션이 그 경로에 있어
  테스트가 넣은 두 사람이 사라졌습니다. 테스트가 넣는 행에 `password_hash` 를 채워
  해결했습니다. `head` 로 두는 것은 의도된 것이라(권한 항목이 늘어도 헤드매니저가 전부
  갖는지 확인) 고정 지점으로 바꾸지 않았습니다.
- **설정 행이 테스트 사이에 삭제되었습니다.** conftest 가 매 테스트마다 모든 테이블을 비우는데
  `settings` 한 줄은 migration 이 넣는 schema 의 일부라 61개가 한꺼번에 실패했습니다.
  건너뛰게 했더니 이번엔 값을 바꾼 테스트가 다음으로 새어서, 삭제하는 대신 기본값으로
  되돌리도록 했습니다.
- **타임라인 막대가 시각 격자를 덮고 있었습니다.** 막대가 절대 위치라 나중에 그려져서
  지나가는 시각 줄을 가렸습니다. 줄을 막대 위로 올렸습니다.
- **dev 서버를 띄우자 `/api/rooms/1/reservations` 가 500 이었습니다(2차).** dev DB 의 migration 이 4개 뒤처져 `reservations.name` 열이 없었습니다. `alembic upgrade head` 로 올렸고, 그 4개 중 "DB 밀기" migration 이 dev 데이터를 삭제했습니다. 로그인 session 도 삭제되어 401 이 이어졌고 다시 로그인해 해결했습니다.
- **편집 게이트 훅이 파일마다 첫 편집을 1회씩 거부했습니다(2차).** 같은 파일에 편집 2개를 보내면 2번째만 적용되어 `hooks.ts`·`Modal.tsx`·`Settings.tsx` 가 잠시 컴파일 불가 상태가 됐습니다. 거부된 편집을 같은 내용으로 다시 보내 해결했습니다. 파일 하나에 여러 편집을 보낼 때는 첫 편집이 들어갔는지 결과를 확인해야 합니다.
- **Docker Desktop 이 꺼져 있어 검사를 돌리지 못했습니다(2차).** 사용자가 켠 뒤 돌렸습니다. 그 사이 구현까지 끝내서 `toast`·`pipeline` 새 테스트 2개는 실패(RED) 단계를 보지 못했습니다. 이후의 `dayEntries`·`assignment`·`slots`·`calendar` 테스트는 RED→GREEN 을 확인했습니다.
