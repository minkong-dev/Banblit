어제 React 이전이 끝난 상태로 시작했습니다. 화면 넷이 서버 데이터로 표시되는데 문서는

### 창이 줄어들면 스크롤이 아니라 창을 막습니다

좁은 창에서 배치가 깨져서 `overflow-y: auto`를 붙였다가 반려되었습니다.
**비율이 유지되지 못해서 틀어질 것 같으면 그냥 그 크기를 지킬 수 있게 처음부터
창이 더 줄어들지 않도록 하세요.** 스크롤은 깨진 배치를 보이지 않게 미룰 뿐이고, 확정된
디자인은 그 비율로 표시되어야 의미가 있다는 뜻입니다. `min-width`/`min-height`로
막고, 그 아래에서만 표시되던 미디어 블록 두 개는 도달할 수 없으니 삭제했습니다.

### 로그인과 CRUD 를 먼저

화면·배포·e2e를 모두 완료해 놓고 **로그인도 만들지 않고 CRUD도 만들지 않으면 결국 무엇을 한 건가요?**라는 지적을 받았습니다. 타당한 지적이었습니다. 제품을 막고 있는 건 화면 개수가 아니라
없는 기능이었습니다. 로그인·가입·토큰, 합주실·기간 CRUD, 명단, 게시판, 예약,
불가능 시간을 그날 안에 모두 만들었습니다.

### 서브에이전트를 한 번에 여러 개

**어차피 서브에이전트를 쓸 거면 왜 한 가지 작업씩만 하나요?** 독립적인 작업을
하나씩 순서대로 실행하고 있었습니다. 이후로는 겹치지 않는 파일 묶음별로 나누어 동시에
실행했습니다. 인증 개선 셋을 서버 세션 / 비밀번호 해시 / 화면 셋으로 나누어 동시에 실행한
것이 그 방식입니다.

### 인증 — JWT 도 리프레시 토큰도 아닙니다

로그인은 어떤 형식으로 인증하고 있는지에 대해 가장 오래 논의한 주제였습니다.

JWT(JSON Web Token)가 아니었습니다. `계정번호.만료시각.서명`을 HMAC-SHA256으로 서명한 것이고,
비밀번호는 표준 라이브러리 `hashlib.scrypt`로 저장하고 있었습니다. 문제 둘을
설명했더니 **JWT로 바꾸면 그 두 개를 해결할 수 있지 않을까요?**라는 제안이 나왔는데,
그렇지 않습니다. 역할을 토큰에 넣는 것은 지금 형식으로도 가능한 payload(토큰에 포함된 데이터) 선택이고,
브라우저 저장소 문제는 형식이 아니라 **어디에 저장하는가**의 문제입니다. JWT로
바꾸면 얻는 것은 외부 도구와 연계할 때의 표준 호환성뿐입니다.

그래서 셋으로 정리했고 그대로 승인받았습니다.

1. **세션을 데이터베이스에 저장합니다.** 서버가 토큰을 취소할 수 있어야 합니다. 지금까지는
   비밀번호를 바꾸거나 기기를 잃어도 7일을 기다려야 했습니다.
2. **토큰을 httpOnly 쿠키로 전송합니다.** 페이지에서 실행되는 스크립트가 읽을 수 없게 합니다.
3. **비밀번호 해시에 계산 강도를 함께 저장합니다.** 그렇지 않으면 강도를 나중에 올릴 수 없습니다.

**리프레시 토큰은 사용하지 않기로 했습니다.** 리프레시 토큰은 서버가 토큰을 취소할 수 없을 때 노출
기간을 줄이기 위한 임시 방편인데, 1번을 하면 바로 끊을 수 있으니 나눌 이유가 없습니다.
나누면 endpoint가 하나 늘고 화면도 갱신 흐름을 알아야 합니다.

1번을 구현한 뒤 서명이 필요 없어졌습니다. 데이터베이스에 행이 없으면 어차피
무효이므로 서명이 추가하는 가치가 없습니다. `secrets.token_urlsafe(32)` 난수로 바꾸고
`AUTH_SECRET_KEY` 환경변수를 삭제했습니다.

## 트러블슈팅

### 로그를 잘못 읽고 "됐다" 고 했습니다

- **언제**: 개발 서버가 화면을 표시하지 못하는 것을 확인하던 중
- **무엇이**: `docker compose logs web`에서 "ready in" 줄을 보고 현재 실행된 것으로 읽었습니다
- **왜**: 그것은 **어제 시작한 줄**이었습니다. 로그는 컨테이너 전체 수명 동안의 내용을 담는데
  시각을 확인하지 않았습니다
- **어떻게**: `--since $(docker inspect ... StartedAt)`으로 이번 시작 이후만 봅니다.
  `COMMAND.md` 10-1에 기록했습니다

### 파일을 고쳐도 브라우저에 반영이 안 됐습니다

- **언제**: 화면 코드를 수정하는데 계속 이전 화면이 표시될 때
- **무엇이**: Vite 개발 서버가 파일 변경을 감지하지 못했습니다
- **왜 (잘못된 진단)**: 제 코드가 잘못되었다고 판단해 계속 수정했습니다
- **왜 (실제)**: Windows 바인드 마운트에서 inotify가 호스트 파일시스템의 변경을
  컨테이너로 전달하지 못했습니다. 코드 문제가 아니었습니다
- **어떻게**: `vite.config.ts`에 `server.watch.usePolling`을 활성화했습니다.
  **어제(9월 3일) "Vite가 추적하지 못했습니다"라고 적은 것의 실제 원인도 이것이었습니다**

### `/teams` 가 화면 주소이면서 서버 통로였습니다

- **언제**: 팀 찾기 화면을 연결할 때
- **무엇이**: 개발 서버가 `/teams`를 화면 주소로 처리해 HTML을 200으로 반환했습니다.
  화면은 그것을 JSON으로 읽으려다 실패했습니다
- **왜**: 화면 주소와 서버 endpoint(API의 요청 주소 단위)가 같은 이름을 사용하면 어느 쪽인지 구분할 방법이 없습니다
- **어떻게**: 서버 endpoint에 `/api` 접두사를 붙였습니다. 붙이는 위치는 `api.ts` 한 곳,
  제거하는 위치는 개발(`vite.config.ts`)과 배포(`nginx.conf.template`) 두 곳뿐입니다

### `min-height` 를 넣었는데 아무 일도 안 일어났습니다

- **언제**: 창을 줄이지 못하게 막으라는 지시를 이행하던 중
- **무엇이**: `min-height`를 추가하고 완료했다고 보고했는데 변화가 없었습니다
- **왜**: 내부 요소들이 `height: 100vh` / `calc(100vh - 62px)`로 **뷰포트에 묶여**
  있었습니다. 외부에 최소 높이를 주어도 내부는 계속 뷰포트를 따라 줄어듭니다
- **어떻게**: `max(100vh, var(--minh))`로 변경했습니다. 창이 그보다 작아지면 뷰포트가
  아니라 최소값을 사용합니다
- **남은 것**: 최소 크기 값(1060×740)은 여전히 계산으로 산출한 값입니다. 캘린더 칸이
  `grid-auto-rows: 1fr`이므로 최소 높이가 없어 무한정 압축되기만 하고 레이아웃이 완전히 깨지지는
  않으므로, 겹침 여부로 판정하는 자동 측정이 항상 통과합니다. 눈으로 확인해야 합니다

### 하드코딩된 팀 번호를 E2E 가 잡아냈습니다

- **언제**: e2e를 처음 실행했을 때
- **무엇이**: 화면이 `FALLBACK_TEAM_IDS = [1,2,3,4]`를 포함하고 있었고 시드가 바뀌자 실패했습니다
- **왜**: **한 에이전트에게는 "그 번호를 유지하세요"라고 지시하면서 동시에 다른
  에이전트에게 `/teams` endpoint를 만들도록 했습니다.** 같은 세션에서 서로 충돌하는 지시를
  내린 것입니다
- **어떻게**: 저장소 전체에서 하드코딩된 번호를 찾아 제거했습니다. 사람도 팀도 모두 서버가
  제공하는 번호로만 처리합니다

### 오늘 만든 코드가 오늘 규약을 어기고 있었습니다

- **무엇이**: `require_account`가 적용된 라우터가 게시판 하나뿐이었습니다.

## 남은 것

### 보안 — 먼저 해야 합니다

- **서버 endpoint 다섯 개에 권한 검사가 없습니다.** `rooms`·`periods`·`roster`·
  `unavailable`·`reservations`에 `require_account`를 추가하고, 기획서의 역할 표에 따라
  헤드매니저만 가능한 것과 본인만 가능한 것을 구분해야 합니다. 현재는 누구나 모두 가능합니다
- 스키마의 `requested_by`·`member_id`를 요청 본문에서 받는 위치들은 토큰의
  주인으로 대체해야 합니다. 코드 주석에 "로그인이 추가되면"이라고 적어둔 위치들입니다

### 핵심 기능인데 없는 것

- **하루 두 번 자동 계산이 실행되지 않습니다.** `periods.first_run_at`·`second_run_at`은
  저장·수정되지만 그 시각에 배정을 실행하는 코드가 저장소에 없습니다. 현재는 사람이
  버튼을 눌러야만 계산이 진행됩니다
- **조율안을 선택해 확정하는 endpoint가 없습니다.** 계산이 실패하면 "누구를 제외하면 된다"는
  안을 만들어 보여주는데, 그것을 현행 시간표로 확정할 수 없습니다
- **되돌리기 버튼이 없습니다.** `POST /periods/{id}/rollback`은 작동하지만 누를 위치가 없습니다
- 배정 실행 알림 — 알림 수단 자체가 저장소에 없습니다

### 양쪽 다 있는데 선만 안 이은 것

- 스케줄러 오른쪽 공지 목록이 예시 글 세 줄로 고정되어 있습니다 (`/notices`는 이미 있습니다)
- 그날 참가하는 사람 목록이 연동되지 않았습니다 (`/teams/{id}/members`는 이미 있습니다)
- 스케줄러 프로필 카드만 "이도현 · 일반멤버"로 고정되어 있습니다. 다른 화면은 실제 값을 표시합니다
- 지난 계산 회차 목록 — 백업 표와 롤백은 있는데 회차를 조회하는 endpoint가 없습니다
- 예약할 때 합주실을 선택하는 위치가 없습니다 — 첫 번째 방으로 고정되어 있습니다
- 주 보기에서 주를 이동할 수 없습니다 — 그 달 15일이 포함된 주만 표시됩니다
- 불가능 시간의 매주 반복을 활성화할 위치가 없습니다 (서버·표는 모두 작동합니다)
- 설정 화면이 팀 수를 사람이 입력받도록 하고 있습니다 (`/teams`가 인원까지 제공합니다)

### 외부 수단이 있어야 하는 것

- 아이디 찾기·비밀번호 찾기·재설정 — 화면 셋은 있지만 작동만 시뮬레이션합니다.
  메일을 보내는 수단이 필요합니다
- 소셜 로그인(구글·카카오) — 버튼이 비활성화 상태입니다. 외부 API 키가 필요합니다

### 기획에 있는데 손도 안 댄 것

- 게시판 파일 첨부
- 예약 시간 변경 (취소는 작동합니다)
- 권한 위임, 필요한 권한 묶음을 모아 새로운 권한 만들기 — **어떤 권한을 묶을 수 있게
  할지가 기획에 정해져 있지 않습니다.** 이것을 먼저 정해야 합니다
- 팀 참가 신청·승인 (자동/직접) — 현재는 신청하면 즉시 가입됩니다
- 집중 합주기간 "매일" 옵션 — 칸은 있지만 배정 계산이 이것을 참고하지 않습니다
- "로그인 상태 유지" 체크박스가 작동하지 않습니다 — 만료 시간은 항상 7일입니다
- LLM 도우미 — 0%

### 문서가 밀린 것

  세션 표가 빠져 있습니다. paper 전체가 뒤처져 있어 한 줄만 추가하면 오히려 정렬이 어긋납니다
- `.cluedoc/screens/README.md`의 `팀별 명단` 줄이 아직 "미연동"으로 남아 있습니다.
  endpoint는 이미 있고 팀 화면·프로필이 사용하고 있습니다

### 미뤄둔 빚

- 만료된 세션 행이 쌓입니다. 주기적으로 삭제하는 기능을 만들지 않았습니다 (`auth_session.py`의 `ponytail:` 주석 참고)
- `test_board_endpoints.py`가 요청마다 쿠키를 전달해서 httpx가 폐지 예정 경고를 냅니다.

  `dialog` 같은 요소 선택자를 사용하고 있어 그것만으로는 충분하지 않습니다
