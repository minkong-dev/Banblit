# 2026-09-04 — 화면을 다 세우고, 로그인을 만들고, 그 로그인이 반쪽인 걸 마지막에 알았다

## 오늘의 출발점

어제 React 이전이 끝난 상태로 시작했다. 화면 넷이 서버 데이터로 뜨는데 문서는
프로토타입 두 벌 시절 그대로였다. "문서부터 일단 고쳐봐" 로 시작해서, 그다음
순서를 이렇게 정했다 — **화면을 다 만들고, E2E 로 검증하고, 그다음 배포.**

## 결정한 것들

### 배정 요청을 비동기로

배정 계산이 8월 28일 실측 0.3초라 동기로 둬도 지금은 돌아간다. 그런데 팀·기간이
늘면 몇 초가 되고, 그 사이 그 서버는 아무것도 못 한다. `/health` 도 못 답한다.
"걍 비동기로 해" 로 결정했고, 접수(202 + 작업 번호) → 되묻기(`GET /jobs/{id}`)
구조로 갔다. 실측했다 — 접수 5밀리초, 계산 도는 동안 `/health` 200.

근거 셋을 `AUDIT.md` 4부에 적었는데 오늘 그 파일은 `trash/` 로 보냈다. 요지는
문서 `.cluedoc/auto-assignment/README.md` 에 남겼다.

### 창이 줄어들면 스크롤이 아니라 창을 막는다

좁은 창에서 배치가 깨지길래 `overflow-y: auto` 를 붙였다가 반려당했다.
**"비율이 유지 못해서 틀어질 것 같으면 그냥 그 사이즈를 지킬 수 있게 아예 창이
더 안 줄어들게 하라"** — 스크롤은 깨진 배치를 보이지 않게 미룰 뿐이고, 확정된
디자인은 그 비율로 보여야 의미가 있다는 것이다. `min-width`/`min-height` 로
막고, 그 아래에서만 살아나던 미디어 블록 두 개는 도달할 수 없으니 지웠다.

### 로그인과 CRUD 를 먼저

화면·배포·E2E 를 다 해놓고 **"로그인도 안 만들고 CRUD도 안 만들고 그럼 넌 대체
뭘 한 거냐"** 를 들었다. 맞는 지적이었다. 제품을 막고 있는 건 화면 개수가 아니라
없는 기능이었다. 로그인·가입·토큰, 합주실·기간 CRUD, 명단, 게시판, 예약,
불가능시간을 그날 안에 다 만들었다.

### 서브에이전트를 한 번에 여러 개

**"어차피 서브에이전트 쓸 거면 왜 한 가지 태스크씩 하는데"** — 독립적인 작업을
하나씩 순서대로 돌리고 있었다. 이후로는 겹치지 않는 파일 묶음별로 나눠 동시에
띄웠다. 인증 개선 셋을 서버 세션 / 비밀번호 해시 / 화면 셋으로 갈라 동시에 돌린
게 그 방식이다.

### 인증 — JWT 도 리프레시 토큰도 아니다

"로그인은 뭘로 인증하고 있는데? JWT?" 로 시작해서 제일 오래 이야기한 주제다.

JWT 가 아니었다. `계정번호.만료시각.서명` 을 HMAC-SHA256 으로 서명한 것이고,
비밀번호는 표준 라이브러리 `hashlib.scrypt` 로 저장하고 있었다. 문제 둘을
말했더니 **"JWT로 바꾸면 그 두 개를 해결할 수 있는 거 아니야"** 가 나왔는데,
그렇지 않다. 역할을 토큰에 넣는 건 지금 형식으로도 되는 payload 선택이고,
브라우저 저장소 문제는 형식이 아니라 **어디에 두느냐** 의 문제다. JWT 로
바꾸면 얻는 건 외부 도구와 물릴 때의 표준 호환뿐이다.

그래서 셋으로 정리했고 그대로 승인받았다.

1. **세션을 데이터베이스가 든다** — 서버가 토큰을 취소할 수 있게. 지금까지는
   비밀번호를 바꾸거나 기기를 잃어도 7일을 기다려야 했다.
2. **토큰을 httpOnly 쿠키로** — 페이지에서 도는 스크립트가 못 읽게.
3. **비밀번호 해시에 계산 강도를 함께 저장** — 안 하면 강도를 영영 못 올린다.

**리프레시 토큰은 하지 않기로 했다.** 그건 서버가 토큰을 취소 못 할 때 노출
기간을 줄이려는 우회책인데, 1번을 하면 바로 끊을 수 있으니 나눌 이유가 없다.
나누면 통로가 하나 늘고 화면도 갱신 흐름을 알아야 한다.

1번을 하고 나니 서명이 필요 없어졌다 — 데이터베이스에 행이 없으면 어차피
무효라 서명이 더해주는 게 없다. `secrets.token_urlsafe(32)` 난수로 바꾸고
`AUTH_SECRET_KEY` 환경변수를 지웠다.

## 트러블슈팅

### 로그를 잘못 읽고 "됐다" 고 했다

- **언제**: 개발 서버가 화면을 못 내보내는 걸 확인하던 중
- **무엇이**: `docker compose logs web` 에서 "ready in" 줄을 보고 지금 뜬 것으로 읽었다
- **왜**: 그건 **어제 기동한 줄**이었다. 로그는 컨테이너 수명 전체를 담는데
  시각을 안 봤다
- **어떻게**: `--since $(docker inspect ... StartedAt)` 로 이번 기동 이후만 본다.
  `COMMAND.md` 10-1 에 적었다

### 파일을 고쳐도 브라우저에 반영이 안 됐다

- **언제**: 화면 코드를 고치는데 계속 옛 화면이 뜰 때
- **무엇이**: Vite 개발 서버가 파일 변경을 아예 못 봤다
- **왜 (오진)**: 내 코드가 틀렸다고 보고 코드를 계속 고쳤다
- **왜 (실제)**: Windows 바인드 마운트에서 inotify 가 호스트 파일시스템의 변경을
  컨테이너로 전달하지 못한다. 코드 문제가 아니었다
- **어떻게**: `vite.config.ts` 에 `server.watch.usePolling` 을 켰다.
  **어제(9월 3일) "Vite 가 따라오지 못했다" 고 적은 것의 진짜 원인도 이거였다**

### `/teams` 가 화면 주소이면서 서버 통로였다

- **언제**: 팀 찾기 화면을 붙일 때
- **무엇이**: 개발 서버가 `/teams` 를 화면 주소로 처리해 HTML 을 200 으로 돌려줬다.
  화면은 그걸 JSON 으로 읽으려다 실패했다
- **왜**: 화면 주소와 서버 통로가 같은 이름을 쓰면 어느 쪽인지 구분할 방법이 없다
- **어떻게**: 서버 통로에 `/api` 접두사를 붙였다. 붙이는 자리는 `api.ts` 한 곳,
  떼는 자리는 개발(`vite.config.ts`)과 배포(`nginx.conf.template`) 두 곳뿐이다

### `min-height` 를 넣었는데 아무 일도 안 일어났다

- **언제**: 창을 못 줄이게 막으라는 지시를 이행하던 중
- **무엇이**: `min-height` 를 넣고 "됐다" 고 보고했는데 그대로였다
- **왜**: 안쪽 요소들이 `height: 100vh` / `calc(100vh - 62px)` 로 **뷰포트에 묶여**
  있었다. 바깥에 최소 높이를 줘도 안쪽은 계속 뷰포트를 따라 줄어든다
- **어떻게**: `max(100vh, var(--minh))` 로 바꿨다. 창이 그보다 작아지면 뷰포트가
  아니라 최소값을 쓴다
- **남는 것**: 최소 크기 값(1060×740)은 여전히 계산으로 낸 값이다. 캘린더 칸이
  `grid-auto-rows: 1fr` 이라 최소 높이가 없어 무한정 눌리기만 하고 "깨지지" 를
  않으니, 겹침으로 판정하는 자동 측정이 항상 통과한다. 눈으로 봐야 한다

### 하드코딩된 팀 번호를 E2E 가 잡아냈다

- **언제**: E2E 를 처음 돌렸을 때
- **무엇이**: 화면이 `FALLBACK_TEAM_IDS = [1,2,3,4]` 를 들고 있었고 시드가 바뀌자 틀렸다
- **왜**: **내가 한 에이전트에게는 "그 번호를 유지하라" 고 지시하면서 동시에 다른
  에이전트에게 `/teams` 통로를 만들게 했다.** 같은 세션 안에서 서로 어긋나는 지시를
  내린 것이다
- **어떻게**: 저장소 전체에서 박아둔 번호를 찾아 없앴다. 사람도 팀도 전부 서버가
  주는 번호로만 다룬다

### 오늘 만든 코드가 오늘 규약을 어기고 있었다

- **언제**: `/refactoring` 감사에서
- **무엇이**: `api` 모듈이 `db` 모듈 파일을 직접 import 하는 자리가 35군데였다.
  모듈 경계 규칙 위반이다
- **왜**: 규약을 알면서도 "일단 만들고 나중에 정리" 로 미뤘다.
  **"오늘 만든 걸 왜 고쳐, 그럴 거면 만들 때부터 고쳐서 만들든가"** 를 들었다.
  맞는 말이다. 나중에 고치는 건 같은 코드를 두 번 쓰는 것이다
- **어떻게**: `db/pipeline.py`·`scheduling/pipeline.py`·`frontend/src/lib/pipeline.ts`
  를 두고 그리로만 지나가게 했다. 35 → 0

### 에이전트들에게 주석 규약을 거꾸로 가르쳤다

- **무엇이**: 초반 에이전트들에게 "주석은 왜를 적어라" 라고 넘겼다
- **왜**: 이 저장소 `refactoring` 스킬 7절은 그 반대다 — **기능 파일에는 무엇을,
  왜는 시퀀스 파일 호출부에.** 위임 지시문을 내가 기억으로 썼다
- **어떻게**: 이후 위임에는 스킬 경로를 지시문에 직접 넣어 읽고 시작하게 했다

### 내가 판단하면 안 되는 걸 판단했다

인증의 약점을 설명하면서 "지금 규모에선 이대로도 됩니다" 라고 결론을 붙였다.
**"지금 규모에서 문제가 될지 안 될지를 왜 네가 판단해"** 를 들었다. 감수할지
말지는 제품과 위험의 문제라 내 것이 아니다. 결론을 빼고 사실과 선택지만 남겼다.

### 로그인을 만들어놓고 통로를 안 잠갔다 — 오늘 제일 큰 것

- **언제**: 마감 직전, 기획서와 코드를 대조하다가
- **무엇이**: `require_account` 가 걸린 라우터가 게시판 하나뿐이었다.
  합주실·기간·명단·불가능시간·예약 다섯은 0건이다
- **결과**: 지금 **로그인하지 않은 사람이** 합주실과 기간을 만들고 고치고,
  남을 아무 팀에나 집어넣고, 남의 불가능 시간을 지우고, 남의 이름으로 예약할 수 있다
- **왜**: 로그인 기능(가입·로그인·토큰·`/me`)을 만드는 것과 그것을 **기존 통로에
  연결하는 것**을 별개 작업으로 나눠 놓고, 앞의 것만 하고 끝냈다고 판단했다.
  기획서 `.cluedoc/accounts-and-roles/README.md` 의 역할 표에 어떤 통로가
  헤드매니저 것인지 다 적혀 있는데 대조를 안 했다
- **어떻게**: 아직 못 고쳤다. 아래 "남은 것" 맨 위에 있다

## 지금 상태

인증 개선 셋을 다 넣었고 컨테이너에 실제로 띄워 직접 확인했다 —
가입하면 `banblit_session` 이 HttpOnly 로 내려오고 응답 본문에 토큰이 없다,
쿠키로 `/me` 가 200, 쿠키 없이 401, 로그아웃 200, 로그아웃한 쿠키로 다시 부르면 401.
데이터베이스에서 세션 행의 취소 표시와 비밀번호가 `scrypt$16384$8$1$…` 형식으로
저장된 것도 눈으로 봤다.

- 서버 테스트 357개 통과, `mypy` 44개 파일 이상 없음
- 화면 테스트 108개 통과, 타입검사 통과, 린트 오류 0 (경고 4)
- 화면 아홉, 서버 통로 일곱 묶음, 배포용 구성(nginx + 배포 base compose) 완료

## 남은 것

### 보안 — 먼저 해야 한다

- **서버 통로 다섯 개에 권한 검사가 없다.** `rooms`·`periods`·`roster`·
  `unavailable`·`reservations` 에 `require_account` 를 붙이고, 기획서 역할 표대로
  헤드매니저만 되는 것과 본인만 되는 것을 갈라야 한다. 지금은 누구나 다 된다
- 스키마의 `requested_by`·`member_id` 를 요청 본문에서 받는 자리들 — 토큰의
  주인으로 대체해야 한다. 코드 주석에 "로그인이 붙으면" 이라고 적어둔 자리들이다

### 핵심 기능인데 없는 것

- **하루 두 번 자동 계산이 안 돈다.** `periods.first_run_at`·`second_run_at` 은
  저장·수정되는데 그 시각에 배정을 돌리는 코드가 저장소에 없다. 지금은 사람이
  버튼을 눌러야만 계산한다
- **조율안을 골라 확정하는 통로가 없다.** 계산이 실패하면 "누구를 빼면 된다" 는
  안을 만들어 보여주는데, 그걸 현행 시간표로 확정할 수가 없다
- **되돌리기 버튼이 없다.** `POST /periods/{id}/rollback` 은 되는데 누를 자리가 없다
- 배정 실행 알림 — 알림 수단 자체가 저장소에 없다

### 양쪽 다 있는데 선만 안 이은 것

- 스케줄러 오른쪽 공지 목록이 예시 글 세 줄로 박혀 있다 (`/notices` 는 이미 있다)
- 그날 나오는 사람 목록이 "미연동" 이다 (`/teams/{id}/members` 는 이미 있다)
- 스케줄러 프로필 카드만 "이도현 · 일반멤버" 가 박혀 있다. 다른 화면은 실제 값이다
- 지난 계산 회차 목록 — 백업 표와 롤백은 있는데 회차를 읽는 통로가 없다
- 예약할 때 방을 고르는 자리가 없다 — 첫 번째 방으로 고정이다
- 주 보기에서 주를 옮길 수 없다 — 그 달 15일이 든 주만 나온다
- 불가능 시간의 매주 반복을 켤 자리가 없다 (서버·표는 다 됨)
- 설정 화면이 팀 수를 사람에게 입력받는다 (`/teams` 가 인원까지 준다)

### 외부 수단이 있어야 하는 것

- 아이디 찾기·비밀번호 찾기·재설정 — 화면 셋은 있는데 성공한 척만 한다.
  메일 보낼 수단이 필요하다
- 소셜 로그인(구글·카카오) — 단추가 `disabled` 다. 외부 열쇠가 필요하다

### 기획에 있는데 손도 안 댄 것

- 게시판 파일 첨부
- 예약 시간 변경 (취소는 됨)
