## 트러블슈팅

### 테스트 292개가 픽스처 단계에서 한꺼번에 터졌다

**왜** 테스트 DB 에 옛 `memberships` 표가 남아 있었다. 픽스처가 `Base.metadata` 를 보고
표 단위로 지우는데, 모델에서 없어진 표는 metadata 가 모르니 남는다. 그 표의 외래키가
`teams` 를 붙들어 `teams` 를 다시 만들 수도 없었다. **어떻게** 스키마를 통째로 비우게
바꿨다(`DROP SCHEMA public CASCADE`). `alembic_version` 도 함께 사라져 따로 지울 필요가
없어졌다.

### 정규식으로 import 줄을 고치다 파일 네 개를 망가뜨렸다

**왜** 여러 줄에 걸친 `from ... import (...)` 를 한 번에 고치려고 정규식을 썼는데,
줄바꿈을 넘어 뒤따르는 주석과 코드까지 삼켰다. **어떻게** `git show HEAD:` 로 원본
import 줄을 꺼내 손으로 되돌렸다. **다음부터** 여러 줄 import 는 정규식으로 훑지 않는다.

### 화면 타입 검사가 0개인데 실제로는 깨져 있었다

**왜** 화면이 서버 응답 타입을 `contract.ts` 에 따로 적어 들고 있어서, 서버가 바뀌어도
타입 검사는 통과한다. 깨지는 것은 실행할 때다. **어떻게** 바뀐 이름(`positions`,
`memberships`, `member_count`, `join_policy`)을 손으로 훑어 찾았다. **남는 것** 이
구조는 그대로다 — 서버와 화면의 타입을 잇는 자리가 없다.

### 그 밖

- `Slot` 이름이 배정 쪽(합주실·시각)과 겹쳐 팀 자리를 `TeamSlot` 으로 나눴다.
- `slotLabel` 이 달력 것과 겹쳐 자리 이름 쪽을 `slotName` 으로 바꿨다.
- `pipeline.ts` 안에서 껍데기 `getJSON` 과 원본 `sendJSON` 으로 갈려 있던 이름을
  하나로 합쳤다 — "연결 끊긴 상태로 보기" 를 걷어내면서 껍데기가 존재 이유를 잃었다.

### 배포

도메인 `banblit.com` 을 Cloudflare 에서 샀고 이 프로젝트는 `in-six-strings.banblit.com`.
Oracle 은 가입 대기 중. Caddy 로 붙이는 것까지 조사만 끝났다.

배포하면 데이터베이스가 서버 한 곳으로 모인다. 그때 두 가지가 새로 생긴다.

- **정기 백업.** 데이터베이스가 `banblit-db-data` Docker 저장 공간 안에만 있다. 주기적으로 파일로 떠서 다른 곳에 두는 자리가 필요하다.
- **데이터베이스를 비울 수 없게 된다.** 구조를 바꿀 때마다 마이그레이션이 기존 데이터를 지키면서 넘어가야 한다.
