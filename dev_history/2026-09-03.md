# 2026-09-03 — 화면을 React 로 옮겼고, 옮기다 디자인을 무너뜨렸다가 되돌렸습니다

## 오늘의 출발점

어제 작업 결과물을 받았습니다. 프로토타입 화면 2개가 서버에 연결되었고, 개발용 시드 데이터가
생겼으며, 서버가 화면을 같은 출처에서 제공하도록 설정되어 있었습니다. "같은 기능을 더 간결하게 구현할 수 있는
부분이 있는지" 먼저 검토해달라고 했습니다.

## 검토에서 나온 것

받은 코드에서 실제 결함 2건, 삭제할 수 있는 중복 790줄을 찾았습니다. 그중 2건을 수정했습니다.

**화면이 무한정 멈출 수 있었습니다.** 브라우저의 `fetch`는 기본 시간 제한이 없습니다.
서버가 응답을 주지 않고 연결을 유지하면 "불러오는 중…" 상태에서 벗어나지 않습니다. 8초 제한을 추가했습니다.
8초 값에 과학적 근거는 없습니다. 조회는 즉시 응답하고 재계산은 8월 28일 실측값 0.3초라서 충분하다고 판단했습니다. 
데이터가 커지면 이 값은 모자랄 수 있습니다.

**접속 시간 제한 검증이 잘못되었습니다.** `raw.strip().lstrip("-").isdigit()`는 앞의 빼기
기호를 전부 제거한 후 검증하므로, `-5`가 통과하고 `--5`는 `int()`에서 실패해 기동 중 종료되었습니다.
`try/except int()`로 수정했습니다.

여기서 지시받은 범위를 넘긴 판단을 하나 했습니다. `--5`만 차단하면 되었는데 음수 전체를 차단했습니다.
근거는 psycopg에서 음수 connect_timeout이 무제한을 의미한다는 문서 정보인데, 실제로 확인하지 않았습니다.
주석에 단정적으로 기록해두었으므로, 잘못되었으면 주석부터 수정해야 합니다.

## React 이전을 화면 단위로 쪼개려 한 것

"어느 부분까지 옮길까요"라고 화면 단위로 질문했습니다. React는 하나의 앱이 여러 경로를 가지는 구조이므로
나눌 이유가 없습니다. 화면 단위로 나누면 기반 구조를 반복해서 구축해야 합니다. **랜딩·로그인·메인·관리자를
하나의 앱에 통합하라고 지시했고**, 그렇게 진행했습니다.

## 컴포넌트를 안 만들고 번역만 했던 것

처음 결과물은 프로토타입 HTML 4개를 각각 "화면 하나"로 보고 1:1로 옮긴 것이었습니다.
JSX로 번역했을 뿐 컴포넌트 분리를 하지 않았습니다. 그 결과 재사용성이 0이었고, 재사용성이 없으니
클래스 이름이 33개 중복되었으며, 중복이 생기니까 CSS scoping이 필요해졌습니다. **스스로 만든
문제를 스스로 해결한 셈입니다.**

지적 후 다시 구성했습니다. 스케줄러와 관리자 화면의 마크업을 실제로 비교해보니 상단바·사이드바·
탭·카드·오른쪽 패널이 거의 동일했습니다. 클래스가 중복된 것은 우연이 아니라 같은 컴포넌트이기 때문이었습니다.

- `AppShell` — 상단바 + 사이드바 + 본문 격자 + 알림
- `Card` `Tabs` `Panel` — 2개 화면이 함께 사용합니다
- `icons.tsx` — 각 화면에 분산되어 있던 SVG 11개
- `Field` — 계정 설정 5개 서식이 공유합니다

## 로그인·회원가입을 한 라우트에 묶었던 것

`view` 상태로 5개 서식을 교체하는 방식이었습니다. 회원가입에 독립된 URL이 없고,
뒤로 가기 동작이 맞지 않으며, 비밀번호 재설정의 진입점이 없습니다. 메일 링크에서 들어오는
`/reset-password?token=...`을 처리할 자리가 전혀 없는 구조였습니다.

통합으로 얻는 것은 왼쪽 사진이 다시 렌더링되지 않는 것 하나뿐인데, layout route로
나누어도 같은 효과를 얻습니다. 부모 컴포넌트가 마운트된 채로 자식만 변경됩니다. **양쪽 이점을 모두 얻는 방법을
떠올리지 못한 것이지, 통합해야 할 기술적 이유가 있었던 것이 아닙니다.** 5개 경로로 분리했습니다.

## 트러블슈팅 — 디자인을 훼손하고 원인을 2번 오진했습니다

- **언제**: 컴포넌트를 공유하도록 리팩토링하면서
- **증상**: 브라우저에서 실행했을 때 패널 머리글·프로필 버튼·팀 목록이 모두 흰색 배경의 알약 모양으로 표시되었습니다.
  확정된 디자인이 눈에 띄게 훼손되었습니다.
- **1차 오진**: `button { background: none }` 한 줄이 빠졌다고 진단했습니다.
  화면 하나만 보고 "한 줄"이라고 단정했습니다. **실제 차이 규모를 정량화하지 않았습니다.**
- **실제 원인 1**: 측정 결과 원본 규칙 330개 중 78개가 달랐습니다. 2개 화면의 CSS 587줄을
  육안으로 검토하면서 "이것은 공통, 이것은 고유"로 분류한 것이 원인이었습니다. 처음 `sed`로 추출할 때는
  오류가 없었는데, 육안 병합 과정에서 누락되었습니다.
- **실제 원인 2**: 원본을 다시 추출해 삽입하고 328/330이 일치함을 확인했는데도
  화면은 변하지 않았습니다. 브라우저까지 규칙이 도착하는 것도 확인했습니다. **개발 서버가
  이미 제거된 CSS를 계속 제공하고 있었습니다.** 서버가 실행 중인 상태에서 파일을 교체해서
  Vite가 변경을 감지하지 못했던 것입니다.
- **조치**: 육안 병합 결과를 `trash/`로 이동하고 원본을 `sed`로 다시 추출해 삽입했습니다.
  컨테이너를 재시작하니 정상화되었습니다. 원본 프로토타입과 나란히 실행해 비교 검증했습니다.
- **남은 제약**: CSS scoping은 최종 형태가 아닙니다. 정석은 CSS Modules인데, 현재 CSS가
  `dialog` 같은 요소 선택자를 사용하고 있어 scoping만으로는 불충분합니다. 확정된 디자인을
  모두 옮긴 후에 별도로 처리할 작업입니다.

## 설명 방식을 2번 지적했습니다

**기술 용어를 임의의 한글 비유로 바꾸어 설명한 것.** "껍데기를 씌워 가뒀다"(CSS scoping),
"글자로 박혀 있던 그림"(base64), "빨간불"(실패하는 테스트). 원래 용어를 모르기 때문에 못 읽는 것이 아니라,
비유를 원래 용어로 역추측해야 해서 이해하기 어렵습니다. 전역 규칙 2장의 "영어 용어를 그대로 쓴다"를
용어 치환으로 오해한 결과입니다. 같은 규칙에 "사용자가 유추해야 이해되는 설명은 잘못된 설명"이 함께 있으며,
`refactoring` 스킬 7절에서 이를 명시적 위반으로 지정합니다.

**"무엇을 수정했나"를 물었을 때 파일 목록을 나열한 것.** 알고 싶은 것은 위임한 결정을 어떤 근거로
내렸는지입니다. 파일 목록은 `git diff`에 있습니다.
