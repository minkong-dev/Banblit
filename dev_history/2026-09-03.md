# 2026-09-03 — 화면을 React 로 옮겼고, 옮기다 디자인을 무너뜨렸다가 되돌렸다

## 오늘의 출발점

집에서 한 작업을 받아 왔다. 프로토타입 화면 두 개가 서버에 붙었고, 개발용 시드가
생겼고, 서버가 화면을 같은 출처로 내보내게 돼 있었다. "같은 기능을 더 짧게 쓸 수
있는 곳이 있는지" 부터 보라고 했다.

## 검토에서 나온 것

받은 코드에서 실제 결함 둘, 지울 수 있는 중복 790줄을 찾았다. 그중 둘을 고쳤다.

**화면이 영원히 멈출 수 있었다.** 브라우저의 `fetch` 는 기본 시간 제한이 없다.
서버가 답을 안 주고 붙잡고 있으면 "불러오는 중…" 에서 끝나지 않는다. 8초 제한을 붙였다.
8초라는 값에 근거는 없다 — 조회는 즉시 오고 재계산은 8월 28일 실측 0.3초라 넉넉하다고
판단한 것이다. 데이터가 커지면 모자란다.

**접속 시간 제한 검사가 틀렸다.** `raw.strip().lstrip("-").isdigit()` 이 앞의 빼기
기호를 전부 떼고 검사해서, `-5` 가 통과하고 `--5` 는 `int()` 에서 터져 기동 중에
죽었다. `try/except int()` 로 바꿨다.

여기서 내가 시킨 범위를 넘은 판단을 하나 했다 — `--5` 만 막으면 됐는데 음수도
막기로 했다. 근거는 psycopg 에서 음수 connect_timeout 이 무제한이라는 것인데,
문서 기준이고 실측하지 않았다. 주석에 단정적으로 적어놨으니 틀렸으면 주석부터 고쳐야 한다.

## React 이전을 화면 단위로 쪼개려 한 것

"어디까지 옮길까요" 를 화면 단위로 물어왔다. React 는 앱 하나에 경로가 여러 개인
구조라 쪼갤 이유가 없다. 쪼개면 뼈대를 두 번 세운다. **랜딩·로그인·메인·관리자를
한 앱에 붙이라고 했고**, 그렇게 갔다.

## 컴포넌트를 안 만들고 번역만 했던 것

처음 결과물은 프로토타입 HTML 네 개를 각각 "화면 하나" 로 보고 1:1 로 옮긴 것이었다.
JSX 로 번역만 했지 컴포넌트를 나눈 게 아니었다. 그래서 재사용이 0 이었고, 재사용이
0 이니 클래스 이름이 33개 겹쳤고, 겹치니까 CSS scoping 이 필요해졌다. **스스로 만든
문제를 스스로 푼 꼴이다.**

지적하고 다시 짰다. 스케줄러와 관리자 화면의 마크업을 실제로 맞춰 보니 상단바·사이드바·
탭·카드·오른쪽 패널이 거의 같았다. 클래스가 겹친 건 우연이 아니라 같은 컴포넌트라서다.

- `AppShell` — 상단바 + 사이드바 + 본문 격자 + 알림
- `Card` `Tabs` `Panel` — 두 화면이 함께 쓴다
- `icons.tsx` — 화면마다 박혀 있던 SVG 11개
- `Field` — 계정 서식 다섯 벌이 쓴다

## 로그인·회원가입을 한 라우트에 묶었던 것

`view` state 로 서식 다섯 개를 갈아 끼우는 방식이었다. 회원가입에 URL 이 없고,
뒤로 가기가 어긋나고, 비밀번호 재설정에 진입점이 없다. 메일 링크로 들어오는
`/reset-password?token=...` 을 받을 자리가 아예 없는 구조였다.

묶어야 얻는 것은 왼쪽 사진이 다시 안 그려지는 것 하나뿐인데, 그건 layout route 로
나눠도 얻는다. 부모가 마운트된 채 자식만 바뀐다. **양쪽을 다 얻는 방법을 안 떠올린
것이지, 묶어야 할 이유가 있었던 게 아니다.** 다섯 개로 나눴다.

## 트러블슈팅 — 디자인을 무너뜨리고 원인을 두 번 오진했다

- **언제**: 컴포넌트를 공유하게 만들면서
- **무엇이**: 브라우저에 띄우니 패널 머리글·프로필 버튼·팀 목록이 전부 흰 알약이 됐다.
  확정된 디자인이 눈에 띄게 망가졌다
- **왜 (1차 오진)**: `button { background: none }` 한 줄이 빠졌다고 진단했다.
  화면 하나만 보고 "한 줄" 이라고 단정했다. **실제로 얼마나 어긋났는지 세지 않았다**
- **왜 (실제 원인 1)**: 세어 보니 원본 규칙 330개 중 78개가 달랐다. 두 화면의 CSS 587줄을
  **손으로** 보며 "이건 공통, 이건 고유" 로 가른 게 원인이다. 처음 `sed` 로 자를 때는
  한 글자도 안 틀렸는데, 손으로 합치면서 흘렸다
- **왜 (실제 원인 2)**: 원본을 다시 잘라 넣고 328/330 이 일치하는 걸 확인했는데도
  화면은 그대로였다. 브라우저까지 규칙이 도착하는 것도 확인했다. **개발 서버가
  이미 지운 CSS 를 계속 물리고 있었다.** 서버가 도는 중에 파일을 갈아엎어서
  Vite 가 따라오지 못한 것이다
- **어떻게**: 손으로 합친 것을 `trash/` 로 보내고 원본을 `sed` 로 다시 잘라 넣었다.
  컨테이너를 다시 띄우니 정상이 됐다. 원본 프로토타입과 나란히 띄워 비교했다
- **남는 영향**: CSS scoping 은 최종형이 아니다. 정석은 CSS Modules 인데, 지금 CSS 가
  `dialog` 같은 element selector 를 쓰고 있어 그것만으로는 안 잡힌다. 확정 디자인을
  다 옮긴 뒤에 따로 할 일이다

## 설명 방식을 두 번 지적했다

**기술 용어를 임의의 한글 비유로 바꿔 설명하는 것.** "껍데기를 씌워 가뒀다"(CSS scoping),
"글자로 박혀 있던 그림"(base64), "빨간불"(실패하는 테스트). 원래 용어를 몰라서 못 읽는 게
아니라, 비유를 원래 용어로 역추측해야 해서 못 읽는다. 전역 규칙 2장의 "영어 용어를 쓰지
않는다" 를 용어 치환으로 오해한 결과다. 같은 장에 "사용자가 유추해야 이해되는 설명은
잘못된 설명" 이 함께 있고, `refactoring` 스킬 7절은 이걸 명시적 위반으로 둔다.

**"무엇을 바꿨나" 를 물었을 때 파일 목록을 나열한 것.** 내가 알고 싶은 건 위임한
결정을 어떻게 내렸는지다. 파일 목록은 `git diff` 에 있다.
