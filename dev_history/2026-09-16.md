### 블라인드

부적절한 글을 처리할 방법이 삭제뿐이었습니다. 삭제는 되돌릴 수 없고 내용도 남지 않습니다.
지우지 않고 가리는 블라인드를 추가했습니다.

`posts.blinded_at` 한 열입니다. 값이 있으면 가려진 글이고 목록·상세에서 빠집니다. 작성자 본인도
볼 수 없습니다. 댓글에는 열을 두지 않았습니다 — 댓글은 글에 딸린 것이라 글이 가려지면 함께 가려집니다.
조회 조건이 전부 `blinded_at IS NULL` 이라 그 조건의 부분 index 를 함께 두었습니다.

- endpoint 3개를 추가했습니다 — `GET /blinded-posts`, `PUT /posts/{id}/blind`,
  `DELETE /posts/{id}/blind`. 전부 `board_moderate` 가 필요합니다
- 화면은 설정의 "블라인드" 탭 하나(`frontend/src/routes/SettingsBlinded.tsx`)와 글 상세의
  블라인드 버튼입니다. 탭은 예약 탭과 같은 구조라 새 모양을 만들지 않고 그대로 따랐습니다
- **남의 글 수정을 권한자에게도 막았습니다.** 전에는 서버가 허용하고 화면만 버튼을 감췄습니다.
  `update_post`·`update_comment` 가 `allow_moderator=False` 로 호출합니다
- **권한자는 팀 소속을 확인하지 않습니다.** 확인하면 그 팀에 속하지 않은 관리자가 부적절한 글을
  아무것도 처리할 수 없습니다. 삭제·블라인드·해제와 가려진 글 목록이 전부 소속을 보지 않습니다

- 동작 규칙은 `.cluedoc/boards/README.md` 의 "블라인드는 지우지 않고 가립니다" 절에 적었습니다
- 리뷰에서 지적받은 "누가 가렸는지 기록이 없다" 를 같은 세션에서 반영했습니다. `posts.blinded_by_id` 를

### 권한 집합 race

모든 권한 항목을 가진 permission set(full set)이 2개 남은 상태에서 두 요청이 각각 1개씩 같은 순간에
삭제하면, 둘 다 "다른 1개가 있다" 를 확인하고 통과해 full set 이 0개가 됐습니다. 0개가 되면 권한을
부여할 사람이 사라지고 되돌릴 방법이 없습니다.

`backend/src/backend/services/permission_service.py` 의 `_require_another_full_set` 이 조회할 때
`with_for_update()` 로 full set 행 전체를 번호 오름차순으로 잠그도록 변경했습니다. `id != set_id`
필터와 `limit(1)` 을 빼고 파이썬에서 자기 자신을 제외합니다. 대상 자신도 함께 잠가야 두 요청이
같은 순서로 잠급니다 — 서로 다른 부분집합을 반대 순서로 잠그면 둘이 서로를 기다립니다.

- 검증: `backend/tests/integration/db/test_permission_endpoints.py::test_two_concurrent_deletes_keep_one_full_set`
  이 두 스레드를 barrier 로 같은 순간에 출발시켜 각각 1개씩 삭제하고, 남은 full set 이 1개인지와
  예외가 `ValueError` 1건인지를 확인합니다. 잠금을 빼면 0개가 되어 실패합니다.
  실행은 `docker compose run --rm dev pytest -q tests/integration/db/test_permission_endpoints.py` 입니다
- 리뷰(`python-reviewer`)는 CRITICAL·HIGH 없음. MEDIUM 2건(스레드 예외를 삼킴, `join` 시간 초과를
  실패로 만들지 않음)은 반영했고, LOW 2건 중 변수 이름 1건을 반영했습니다. 나머지 LOW 1건은
  `permissions` 열에 index 가 없어 조회가 순차 탐색이라는 것으로, 이번 변경 전에도 같았습니다

### 링크 미리보기

크롤러는 JavaScript 를 실행하지 않아 Vite 가 내보내는 `index.html` 만 읽습니다. 그 파일에 태그가
없어 카카오톡·페이스북에 주소를 붙여넣으면 제목·설명·이미지가 나오지 않았습니다.

`frontend/index.html` 에 `og:*` 와 `twitter:card` 를 넣었습니다. **서버(FastAPI)는 건드리지
않았습니다** — `index.html` 을 내보내는 것은 서버가 아니라 nginx 입니다(`frontend/nginx.conf.template`).
서버에 주입 코드를 넣으면 그 코드를 지나가는 요청이 없습니다.

`og:image` 는 절대 주소여야 하는데 정적 파일은 자기 주소를 실행 중에 알 수 없으므로, 묶는 시점에
박습니다. `.env` 의 `APP_ORIGIN` → `docker-compose.yml` 의 build arg → `frontend/Dockerfile` 의
`ENV` → Vite 가 `%VITE_APP_ORIGIN%` 을 교체하는 순서입니다. 주소를 새로 만들지 않고 비밀번호 재설정
링크가 쓰는 값을 그대로 쓴 이유는, 사용자가 접속하는 주소와 미리보기 주소가 갈라지지 않게 하기
위해서입니다. 이미지는 `/images/in_six_strings.jpg` 를 임시로 씁니다.

- 검증(개발 경로): `frontend/e2e/account.spec.ts` 의 "링크 미리보기 태그가 첫 화면에 들어 있다" 가
  `og:image` 가 `http://` 또는 `https://` 로 시작하고 `%` 가 남아 있지 않은지 확인합니다
- 검증(배포 경로): E2E 는 개발 서버만 보므로 `COMMAND.md` 10-4-1 을 추가했습니다. 배포용 image 를
  만들고 그 안의 `index.html` 에서 태그를 직접 읽습니다. 실행해 `og:url`·`og:image` 가
  `http://localhost:8080` 으로 채워지는 것을 확인했습니다(이 PC 의 `.env` 에 `APP_ORIGIN` 이 비어
  기본값이 사용됐습니다)
