## 오늘 한 것

### 1. 메일 발송 사유 기록

"메일을 못 받았다"는 문의가 왔을 때 서버가 조건 때문에 보내지 않은 것인지, 보냈는데 도착하지 않은
것인지 구분할 방법이 없었습니다. 네 가지 경우를 기록에 남깁니다 — 발송함 / 일치하는 계정 없음 /
재발송 제한 1분 이내 / 이름 불일치. 계정 번호만 남기고 메일 주소와 token 은 남기지 않습니다.

**기록 수준을 올리는 위치가 쟁점이었습니다.** uvicorn 은 자기 logger 만 설정하고 root 는 설정하지
않아, 그대로 두면 INFO 가 전부 사라집니다. 처음에는 `backend` 전체를 INFO 로 올렸는데,
security-reviewer 가 HIGH 로 지적했습니다 — `mailer` 의 개발용 본문 기록(재설정 token 포함)까지
함께 살아나, `MAIL_LOG_BODY` 를 잘못 설정한 배포에서 token 이 노출됩니다. 허용 목록 방식으로
바꿨습니다. `api/app.py` 는 출력 경로만 만들고, 수준은 기록이 필요한 모듈이 직접 올립니다.

### 2. 입력 규칙

사용자가 비밀번호를 `가나다라마바사아Abc1!` 로 설정한 것을 보고 시작했습니다. 특수기호 규칙이
`[^A-Za-z0-9]` 라 한글이 특수기호로 판정되어 네 규칙을 전부 통과했습니다.

| 칸 | 규칙 | 결정 이유 |
|---|---|---|
| 아이디 | 영어 소문자·숫자 4~20자 | 밑줄을 뺐습니다(사용자 결정) |
| 비밀번호 | 영어·숫자 + 특수문자 23개 목록 | 따옴표·역슬래시·꺾쇠 등은 주소·질의문·명령줄에서 따로 처리해야 하는 글자 |
| 이메일 | 눈에 보이는 ASCII | 한글 주소는 SMTPUTF8 미지원 서버를 지나면 발송이 실패 |
| 이름·학과 | 한글·영어 글자와 낱말 사이 공백 | 학과에 숫자가 섞이면 같은 학과가 다른 학과로 저장되어 동명이인 판정이 어긋남 |

가입 화면은 비밀번호 칸을 누르면 규칙 네 줄을 칸 아래에 표시합니다. 충족 전에는 포인트 색과 ✕,
충족하면 초록과 ✓ 입니다. 확인 칸으로 옮겨도 네 줄은 닫지 않고 일치 여부 한 줄이 붙습니다.

### 3. 프로필

프로필 사진은 계정 1개에 1장입니다. 저장 폴더·조각 단위 쓰기·경로 검사는 게시판 첨부가 쓰던 함수를

사진을 표시하는 자리는 상단바·프로필 카드·프로필 화면 세 곳입니다. **달력과 날짜 모달에는 넣지
않았습니다**(사용자 결정 — 칸이 좁습니다). 멤버 명단·검색 결과·게시글 작성자도 넣지 않았습니다.

## 트러블슈팅

### 메일이 나가지 않던 원인

- **누가·언제**: 로컬에서 재설정 메일을 실제로 보내 본 11:38.
- **무엇이**: `비밀번호 재설정 메일을 발송했습니다 — 계정 1` 뒤 2초에 `메일을 보내지 못했습니다 —
  (535, '5.7.8 Username and Password not accepted ... BadCredentials')` 가 남았습니다.
- **왜**: `.env` 의 `SMTP_PASSWORD` 가 Gmail 앱 비밀번호가 아니었습니다. 개발자님이 값을 받아 넣은
  뒤 다시 보내자 실패 기록 없이 메일이 도착했습니다.
- **어떻게 찾았나**: 이번에 넣은 사유 기록으로 "서버가 보내려 했는가"와 "SMTP 가 받았는가"가
  두 줄로 갈라져 바로 구분됐습니다. 기록이 없었으면 어느 쪽인지 알 수 없었습니다.
- **남은 것**: 배포 서버 `.env` 도 같은 값인지 확인하지 못했습니다.

### 잠금을 넣고도 잠기지 않던 사진 저장

- **무엇이**: 같은 계정으로 사진을 동시에 두 번 올리면 참조되지 않는 파일이 디스크에 쌓입니다.
  security-reviewer 가 CRITICAL 로 지적했습니다.
- **왜**: 두 요청이 커밋 전의 같은 파일명을 읽고 각자 새 파일을 쓴 뒤, 같은 옛 파일 하나만 지웁니다.
- **1차 수정**: 첨부가 쓰는 방식대로 계정 행을 `FOR UPDATE` 로 잠갔습니다.
- **그런데도 실패**: 검사를 "잠금 뒤에 읽은 파일명으로 지우는가"로 바꾸자 실패했습니다. SQLAlchemy
  가 이 session 이 앞서 읽어 둔 값을 그대로 돌려줘, 기다린 뒤에도 옛 파일명을 보고 있었습니다.
  `populate_existing` 을 붙여 해결했습니다.
- **교훈**: 검사를 두 번 고쳐 쓰는 동안 결함이 하나 더 나왔습니다. 처음 만든 검사는 잠금을 빼도
  통과해 아무것도 재지 못했습니다. **검사를 만들면 그 검사가 실패하는 것을 먼저 봐야 합니다.**

### 아이콘을 잘못 재사용

규칙 미충족 표시에 `CloseIcon` 을 가져다 썼습니다. 그것은 모달·드로어·랜딩의 **닫기 버튼** 아이콘이라,
닫기 아이콘을 바꾸면 규칙 목록까지 같이 바뀝니다. 개발자님 지적으로 `CrossIcon` 을 따로 만들었습니다.
✓ 는 기존 `CheckIcon` 을 그대로 씁니다. `CheckMark` 는 안에 체크박스 input 이 있는 부품이라
누를 수 없는 표시 자리에는 쓰지 않았습니다.

### e2e 준비 계정이 새 규칙에 걸림

이름 규칙을 넣자 `E2E 검사`·`E2E 멤버` 의 숫자가 걸려 준비 단계가 멈췄습니다. `검사 계정`·`검사 멤버`
로 바꿨습니다. 가입 검사 두 개도 이름에 시각 값을 붙이고 있어 글자만 쓰도록 고쳤습니다. 사람을
구분하는 값은 학번이라 그대로 둬도 겹치지 않습니다.

### TRUNCATE 가 팀 자리까지 비움

`TRUNCATE members ... CASCADE` 는 참조하는 행만이 아니라 **그 표 전체**를 비웁니다. `team_slots` 가
통째로 비어 모든 팀의 자리 구성이 사라졌습니다. 팀·합주실은 남았습니다. 명령을 안내하면서 이
결과를 미리 말하지 않았습니다.
