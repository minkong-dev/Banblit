## 오늘 한 것

### 1. 프로필 카드가 열렸다 닫힘

화면마다 `<AppShell>` 로 자기를 감싸고 있어서, React 가 화면을 옮길 때 상단바까지 통째로 지우고 새로 만들었습니다.
그 사이 `body[data-shell]` 속성이 잠깐 없어져 프로필 카드가 스타일 없이 계산되고, 속성이 돌아오며 숨겨지는
애니메이션이 재생됐습니다. 09-15 에는 effect 시점만 옮겨 막았는데, 09-21 에 측정 코드가 ref callback 으로 바뀌며 다시 났습니다.

사용자는 "React 가 부분 갱신을 못 하냐, 레퍼런스를 찾아보라" 고 했고, React 공식 문서(Preserving and Resetting State)와
React Router 문서(Layout Routes)로 확인했습니다. 계정 화면은 이미 layout route 였는데 로그인 뒤 화면만 그렇지 않았습니다.
AppShell 을 layout route 로 옮겼습니다. 09-03 에 계정 화면을 layout route 로 만들면서 AppShell 에는 적용하지 않은 것이 원인입니다.

### 2. 화면 폭·스크롤·창 폭 단계

- 사용자는 "넓은 모니터에서 폭을 애매하게 쓴다, 드래그하면 화면이 잘려 밀린다" 고 지적했습니다.
- 본문 최대 폭 1440px 은 09-08 에 제가 임의로 넣은 값이었습니다. 고정값을 쓰지 말라는 지적을 고치면서 다른 고정값을 넣은 것입니다.
  레퍼런스(GitHub Primer PageLayout)는 화면마다 폭을 고르고 페이지 전체가 스크롤하며 사이드바를 sticky 로 둡니다. 이 방식으로 바꿨습니다.
- `body` 를 창 높이로 묶고 `overflow: hidden` 으로 숨긴 구조라, 숨은 스크롤이 드래그로 움직였습니다. 상단바 높이 계산도 테두리 1px 을 빠뜨려 늘 1px 넘쳤습니다(`--bar: 63px`).
- 최소 폭 1060px 과 휴대폰 전환 860px 사이 200px 이 잘렸습니다. 사용자 결정으로 3단계(1060 이상 / 768~1059 / 767 이하)로 나눴습니다.
- 하단 여백은 사용자 결정으로 **대시보드만 창 바닥까지 채우고 나머지는 내용 높이** 입니다. 목록은 쪽당 10줄(`PER_PAGE`)로 바꾸고 `useFitCount` 를 삭제했습니다.
- 모달 너비도 창 폭에 비례합니다(`max(560px, 36vw)`).
- 휴대폰은 사용자 요청으로 햄버거 버튼 + 왼쪽 메뉴 판(Material Design 모달 드로어)입니다. 랜딩 메뉴와 같은 `popover` 방식입니다.

### 3. 달력

- 칸 높이가 너비에 비례합니다(0.75배, 56~137px). 달력 안쪽 스크롤을 없애고 페이지 전체가 스크롤합니다.
- 휴대폰 달력·설정이 깨진 원인: 오른쪽 칸을 2열에 직접 배치해 한 줄 배치에서도 2열이 생겼습니다.
- 주 보기 맨 위 시각 글자가 요일 머리글에 가려지던 것: 글자를 칸 윗선에 걸치게 8px 올려 두었습니다. 칸 안쪽으로 옮겼습니다.
- 대시보드 "내 팀" 이 배정 일정에 나온 팀만 보여 주던 것을 소속 팀 전부로 바꿨습니다.

### 4. 예약

- 사용자: "지난 날짜에 예약이 되고 지울 방법이 없다. 예약일이 지나면 소멸하고 지난 날짜에는 예약이 안 되어야 정상".
  서버가 시작 시각이 지난 예약의 생성·변경을 거절합니다. 예약 모달 오른쪽은 불가능 일정처럼 **내 예약 전부**(끝나지 않은 것)를 보여 주고 거기서 취소합니다.
- 테스트가 실제 오늘 날짜에 흔들리지 않도록 서버의 현재 시각을 `current_time` 의존성으로 뺐습니다.

### 5. 아이디

사용자는 가입에서 아이디를 받는다고 알고 있었지만, 코드를 보니 아이디 칸이 없고 이메일로 로그인하고 있었습니다.

### 카카오 링크 미리보기 (가장 오래 헤맸습니다)

- **누가·언제**: 사용자가 카카오톡에 `in-six-strings.banblit.com` 을 공유할 때, 15:48 부터 17:00 무렵까지.
- **무엇이**: 처음에는 사진이 가운데 기준으로 잘렸고(악기가 잘림), 그 뒤로는 이미지 자리가 회색이었습니다.
- **왜 1 — 잘림**: 카카오는 2:1 로 가운데를 자릅니다. 4:3 원본을 보냈습니다.
- **왜 2 — 옛 이미지 유지**: 같은 파일 이름에 덮어썼습니다. 카카오는 썸네일을 이미지 주소 기준으로 약 100일 저장하고 초기화 도구로도 지워지지 않습니다(데브톡 담당자 답변). 저는 처음에 초기화 도구도 잘못 안내했습니다(공유 디버거가 아니라 `/tool/clear/og`).
- **왜 3 — 회색(1)**: 옛 이미지 파일을 지우고 배포해, 카카오가 그 주소를 요청했을 때 nginx 가 404 대신 `index.html` 을 200 으로 보냈습니다. 카카오가 HTML 을 이미지로 저장했습니다. `/images/` 는 없으면 404 를 내도록 고쳤습니다.
- **왜 4 — 회색(2)**: 사용자가 데브톡에 문의해 받은 답이 원인이었습니다. **카카오 스크랩은 이미지를 3초 안에 받아야 하는데 661KB 이미지가 6초 넘게 걸렸습니다.** 1200px·111KB 로 줄였습니다. `og:image:width/height` 태그를 원인으로 추정해 뺐던 것은 틀린 추정이었습니다.
- **어떻게 찾았나**: Caddy 접속 기록에서 카카오 IP(211.231.103.x, 27.0.238.x 수집기, 121.53.x 썸네일 서버)의 요청과 응답 종류를 대조했습니다.
- **교훈**: 추측으로 설정을 바꾸기 전에 공식 문서와 서버 기록을 먼저 봅니다. 이미지를 바꿀 때는 `?v=` 숫자를 올립니다(`index.html` 주석).
