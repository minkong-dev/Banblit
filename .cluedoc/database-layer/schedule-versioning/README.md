## Abstract

배정 이력과 롤백은 집중기간의 시간표를 다시 짤 때, 이전 시간표를 잃지 않고 되돌릴 수 있게 하는 저장 규칙이다. 현재 쓰이는 시간표는 언제나 한 벌만 두고, 다시 짤 때마다 밀려난 이전 시간표를 저장시각을 찍어 백업으로 옮긴다. 백업은 최근 두 번의 연산분(하루 2회 연산 = 하루치)만 남기고, 롤백은 가장 최근 백업을 현재 시간표로 되돌린다.

## Introduction

집중기간에는 시스템이 하루에 두 번 자동으로 시간표를 다시 짠다. 새로 짠 결과가 이전보다 나쁠 수도 있으므로, 다시 짜기 전의 상태로 한 번 되돌릴 길이 필요하다. 그렇다고 지난 시간표를 무한정 쌓아 둘 이유는 없다 — 되돌리기 위해 필요한 것은 바로 직전의 몇 벌뿐이다.

여기서 풀어야 할 긴장은 두 가지다. 하나는 "현재 시간표는 언제나 한 벌"이어야 한다는 것 — 같은 합주실의 같은 칸에 두 팀이 잡히는 이중 예약은 [데이터 저장소](../README.md)의 칸 단위 중복 금지로 막고 있는데, 이 안전장치는 시간표가 한 벌일 때 성립한다. 다른 하나는 되돌리기 위해 이전 시간표를 여러 벌 들고 있어야 한다는 것. 이 둘을 함께 만족시키려고, 현재 시간표와 백업을 **다른 자리**에 나눠 둔다.

## Description

### 두 자리로 나눈 까닭

현재 시간표는 한 벌만 두는 자리에, 이전 시간표들은 별도의 백업 자리에 둔다. 현재 시간표 자리는 예전 그대로여서, 같은 칸에 배정이 하나만 들어간다는 중복 금지가 계속 지켜진다. 백업 자리는 여러 회차가 공존해야 하므로 그 중복 금지를 두지 않는다 — 대신 각 회차를 **저장시각**으로 구분한다. 한 번의 백업은 저장시각 하나로 묶인 한 벌이고, 저장시각이 있으니 회차끼리 자연히 정렬된다.

| 자리 | 몇 벌 | 구분 방법 | 이중 예약 방지 |
| --- | --- | --- | --- |
| 현재 시간표 | 항상 한 벌 | (구분 불필요) | 합주실 + 시작시각 중복 금지(기존 그대로) |
| 백업 | 여러 회차 | 저장시각 | 두지 않음(회차 하나하나는 이미 완결된 시간표) |

### 다시 짜기의 순서

다시 짤 때는 정해진 순서를 지킨다. 먼저 지금의 현재 시간표를 저장시각을 찍어 백업으로 복사하고, 그다음 현재 시간표를 비우고 새 시간표를 채운다. 복사가 비우기보다 **먼저** 일어나므로, 밀려나는 시간표를 잃는 순간이 없다. 마지막으로 그 기간의 백업이 두 회차를 넘으면 가장 오래된 회차를 지운다.

```
1. 현재 시간표를 백업으로 복사 (저장시각 도장)
2. 현재 시간표를 비우고 새 시간표로 채움
3. 그 기간의 백업이 2회차를 넘으면 가장 오래된 회차 삭제
```

이 순서에는 한 가지 더 미묘한 점이 있다. 현재 시간표를 비우는 일이 새 시간표를 채우는 일보다 먼저 데이터베이스에 반영되어야, 새로 채운 자리가 방금 비운 자리와 같은 칸이어도 중복 금지에 걸리지 않는다. 저장 로직은 이 반영 순서를 지키도록 짜여 있다.

### 되돌리기

롤백은 그 기간의 백업 중 가장 최근 회차를 찾아, 현재 시간표를 그 회차로 되돌리고 되돌린 회차는 백업에서 없앤다. 되돌릴 백업이 하나도 없으면 아무것도 바꾸지 않고 "되돌릴 것이 없다"고만 알린다. 백업을 두 회차까지 들고 있으므로, 한 번 되돌린 뒤에도 그 이전 회차 하나가 남아 다음 되돌리기의 여지가 된다.

### 연결된 곳

이 규칙은 저장 방식만 정한다. "저장된 데이터로 시간표를 짜서 이 저장을 부르는" 통로는 [기간 자동 배정](../../scheduling-api/period-assignment/README.md)의 배정 엔드포인트와 롤백 엔드포인트다. 배정 엔드포인트는 계산이 성공한 결과를 이 저장 규칙에 실어 저장하고, 롤백 엔드포인트는 헤드매니저의 되돌리기 요청을 이 롤백 규칙으로 그대로 처리한다.

### TDD 검증

이 규칙도 실패하는 테스트를 먼저 세운 뒤 통과시키는 방식으로 만들었다. 테스트는 실제 테스트 데이터베이스에 마이그레이션을 적용해 돌아간다.

| 커버하는 시나리오 |
| --- |
| 백업 스냅샷 한 행이 저장시각과 함께 그대로 저장·조회되는지 |
| 그 기간의 첫 저장은 백업 없이 현재 시간표에만 쓰이는지 |
| 다시 저장하면 이전 시간표가 저장시각을 달고 백업으로 옮겨지는지 |
| 여러 번 저장해도 백업이 최근 두 회차만 남는지 |
| 롤백이 직전 시간표를 현재로 되돌리고 그 백업 회차를 없애는지 |
| 되돌릴 백업이 없을 때 롤백이 현재 시간표를 건드리지 않고 실패를 알리는지 |
| 세 번 저장한 뒤 한 번 되돌렸을 때, 그보다 이전 회차 하나가 백업에 그대로 남는지 |
| 두 기간의 저장·오래된 회차 삭제·되돌리기가 서로의 현재 시간표와 백업을 건드리지 않는지 |

실행 커맨드(저장소 루트에서):

```
docker compose run --rm dev pytest tests/test_schedule_store.py -q
```

```
docker compose run --rm dev pytest -q
```

## Conclusion

배정 이력과 롤백은 "현재 시간표는 한 벌, 이전 시간표는 저장시각으로 구분한 백업 두 회차"라는 단순한 나눔으로, 이중 예약 방지를 그대로 지키면서 되돌리기를 얹는다. 이 규칙은 저장 방식까지만 책임지며, 이를 불러 쓰는 배정·롤백 통로는 [기간 자동 배정](../../scheduling-api/period-assignment/README.md)에서 다룬다.
