## Abstract

배정 이력과 롤백은 집중기간의 시간표를 다시 짤 때 이전 시간표를 잃지 않고 되돌릴 수 있게 하는 저장 규칙입니다. 현재 쓰이는 시간표는 언제나 1벌만 두고, 다시 계산할 때마다 교체된 이전 시간표에 저장시각을 기록해 백업으로 옮깁니다. 백업은 최근 2회의 연산분(하루 2회 연산 = 하루치)만 보관하고, 롤백은 가장 최근 백업을 현재 시간표로 되돌립니다.

## Introduction

집중기간에는 시스템이 하루에 2회 자동으로 시간표를 다시 계산합니다. 새로 계산한 결과가 이전보다 나쁠 수도 있으니 다시 계산하기 전의 상태로 되돌릴 방법이 필요합니다. 그렇다고 이전 시간표를 무제한 보관할 이유는 없습니다. 되돌리기 위해 필요한 배정기록은 직전 2개뿐이기 때문입니다.

이 규칙에서 충족해야 할 제약이 2가지 있었습니다. 1번째는 현재 시간표가 언제나 1벌이어야 한다는 제약입니다. 같은 합주실의 같은 slot(1시간 단위 시간 칸)에 팀 2개가 배정되는 이중 예약은 [데이터 저장소](../README.md)의 slot 단위 중복 금지로 막고 있는데, 이 안전장치는 시간표가 1벌일 때만 성립합니다. 2번째는 되돌리기 위해 이전 시간표를 2개 보관해야 한다는 제약입니다. 이 2가지를 함께 충족하려고 현재 시간표와 백업을 다른 table에 나눠 두었습니다.

## Description

### table을 2개로 나눴습니다

현재 시간표는 1벌만 두는 table에, 이전 시간표들은 별도의 백업 table에 둡니다. 현재 시간표 table은 예전 그대로여서 같은 slot에 배정이 1개만 들어간다는 중복 금지가 계속 지켜집니다. 백업 table은 2개 이상 배정기록이 공존해야 하므로 그 중복 금지를 두지 않고, 대신 각 배정기록을 저장시각으로 구분합니다. 1회의 백업은 저장시각 1개로 묶인 1벌이고, 저장시각으로 배정기록끼리 정렬됩니다.

| table | 몇 벌 | 구분 방법 | 이중 예약 방지 |
| --- | --- | --- | --- |
| 현재 시간표 | 항상 1벌 | (구분 불필요) | 합주실 + 시작시각 중복 금지(기존 그대로) |
| 백업 | 최근 2개 배정기록 | 저장시각 | 두지 않음(각 배정기록은 이미 완결된 시간표) |

### 다시 계산할 때는 순서를 지킵니다

먼저 현재의 시간표에 저장시각을 기록해 백업으로 복사하고, 그 다음 현재 시간표를 비우고 새 시간표로 채웁니다. 복사가 비우기보다 먼저 실행되므로 교체된 시간표를 손실하는 순간이 없습니다. 마지막으로 그 기간의 백업이 2개 배정기록을 초과하면 가장 오래된 배정기록을 삭제합니다.

```
1. 현재 시간표를 백업으로 복사 (저장시각 도장)
2. 현재 시간표를 비우고 새 시간표로 채움
3. 그 기간의 백업이 2개 배정기록을 넘으면 가장 오래된 배정기록 삭제
```

이 순서에는 주의점이 1가지 더 있습니다. 현재 시간표를 비우는 작업이 새 시간표를 채우는 작업보다 먼저 데이터베이스에 반영되어야, 새로 채운 자리가 방금 비운 자리와 같은 slot이어도 중복 금지에 걸리지 않습니다. 저장 로직은 이 반영 순서를 지키도록 작성했습니다.

### 되돌리기는 가장 최근 배정기록 1개입니다

롤백은 그 기간의 백업 중 가장 최근 배정기록을 찾아 현재 시간표를 그 배정기록으로 되돌리고, 되돌린 배정기록은 백업에서 삭제합니다. 되돌릴 백업이 0개이면 아무것도 변경하지 않고 "되돌릴 배정기록이 없다"는 결과만 반환합니다. 백업을 2개 배정기록까지 보관하므로, 1회 되돌린 뒤에도 그 이전 배정기록 1개가 남아 다음 되돌리기의 대상이 됩니다.

### 이 규칙은 저장 방식까지만 책임집니다

"저장된 데이터로 시간표를 계산해 이 저장을 호출하는" endpoint(API의 요청 주소 단위)는 [기간 자동 배정](../../scheduling-api/period-assignment/README.md)의 배정 endpoint와 롤백 endpoint입니다. 배정 endpoint는 계산이 성공한 결과를 이 저장 규칙을 통해 저장하고, 롤백 endpoint는 헤드매니저의 되돌리기 요청을 이 롤백 규칙으로 그대로 처리합니다.

### TDD로 검증했습니다

이 규칙도 실패하는 테스트를 먼저 작성한 뒤 통과시키는 방식으로 만들었고, 테스트는 실제 테스트 데이터베이스에 마이그레이션을 적용해 실행됩니다.

| 커버하는 시나리오 |
| --- |
| 백업 배정기록 1행이 저장시각과 함께 그대로 저장·조회되는지 |
| 그 기간의 첫 저장은 백업 없이 현재 시간표에만 저장되는지 |
| 다시 저장하면 이전 시간표가 저장시각과 함께 백업으로 옮겨지는지 |
| 3회 이상 저장해도 백업이 최근 2개 배정기록만 남는지 |
| 롤백이 직전 시간표를 현재로 되돌리고 그 백업 배정기록을 삭제하는지 |
| 되돌릴 백업이 없을 때 롤백이 현재 시간표를 변경하지 않고 실패를 반환하는지 |
| 3회 저장한 뒤 1회 되돌렸을 때, 그보다 이전 배정기록 1개가 백업에 그대로 남는지 |
| 2개 기간의 저장·오래된 배정기록 삭제·되돌리기가 서로의 현재 시간표와 백업을 변경하지 않는지 |

## Conclusion

배정 이력과 롤백은 "현재 시간표는 1벌, 이전 시간표는 저장시각으로 구분한 백업 2개 배정기록"이라는 단순한 구분으로 이중 예약 방지를 그대로 지키면서 되돌리기를 추가했습니다. 이 규칙은 저장 방식까지만 책임지고, 이 규칙을 호출하는 배정·롤백 endpoint는 [기간 자동 배정](../../scheduling-api/period-assignment/README.md)에서 다룹니다.
