## Abstract

합주실과 기간은 "언제, 어떤 규칙으로 합주실을 쓰는가"의 틀을 정한다. 합주실은 기본 한 개이며, 여러 개로 늘릴 수 있다. 합주실마다 여는 시간과 닫는 시간을 따로 정할 수 있고, 자리를 쪼개는 단위는 30분으로 고정한다. 기간은 두 종류다. 평상시의 상시 개방기간은 선착순 예약으로 쓰고, 공연을 앞둔 집중 합주기간에는 시스템이 자동으로 자리를 배정한다.

## Introduction

합주실 운영 방식은 밴드마다, 시기마다 다르다. 평소에는 필요할 때 잡아 쓰지만, 공연을 앞두면 모든 팀이 골고루 연습해야 한다. 이 두 상황을 한 가지 규칙으로 묶으면 어느 한쪽이 불편해진다. 그래서 Banblit은 기간을 상시와 집중으로 나누고, 각 기간에 맞는 사용 방식을 따로 둔다.

## Description

**합주실.** 기본은 한 개다. 다른 밴드에 같은 방식을 제공할 때를 대비해, 합주실을 여러 개로 늘리는 것을 간단한 조작으로 할 수 있도록 설계한다. 합주실은 각각 이름을 갖고, **이름이 겹치면 설정으로 받아들이지 않는다.** 이름이 같으면 배정 결과에서 두 방을 구분할 수 없어 같은 방에 두 팀이 겹쳐 들어간 것처럼 보이기 때문이다.

**운영 시간.** 헤드매니저가 합주실마다 여는 시간과 닫는 시간을 정한다. 방마다 서로 다르게 둘 수 있다.

**자리 단위는 30분 고정.** 자리는 정시와 30분, 이 두 지점에서만 시작한다. 운영 시간도 이 지점에 맞춰야 하며, 어긋나면 잘못된 설정으로 거부한다. 예를 들어 18시 20분에 여는 설정은 받지 않는다. 남는 시간을 조용히 버리면 설정이 틀렸다는 사실을 아무도 모른 채 넘어가기 때문이다.

방마다 여는 시간이 달라도 **자리의 경계는 모든 방이 공유한다.** 1번방의 19시 자리와 2번방의 19시 자리는 같은 시간대다. 그래서 한 사람이 같은 시간에 두 방에 들어가는 일을 막을 수 있다.

**두 기간.**

| 기간 | 사용 방식 | 자동 배정 |
| --- | --- | --- |
| 상시 개방기간 | 선착순 예약 또는 예약 없이 사용 | 없음 |
| 집중 합주기간 | 팀별로 비슷한 합주량이 되도록 배정 | 있음 |

**집중 합주기간의 합주량.** 집중기간에는 모든 팀이 **정확히 같은 개수**의 자리를 갖는다. 예를 들어 매일 저녁 여섯 시간이 2주간 열리고 팀이 여섯이라면, 각 팀이 같은 개수의 30분 자리를 나눠 갖는다. 한 팀이라도 그 개수를 채우지 못하면 배정 전체가 실패로 처리되고, 사람의 판단으로 넘어간다. 항상 자동 배분을 원하는 조직은 집중 합주기간을 "매일" 옵션으로 두어 상시처럼 쓸 수 있다.

**남는 자리.** 팀들이 자리를 받고 남은 칸은 예약 가능한 자리로 함께 나온다. 집중기간에도 비어 있는 시간은 상시처럼 쓸 수 있다.

### 누가 이 값을 넣는가

헤드매니저가 설정 화면에서 넣는다. 규칙은 **세 곳에서 같은 것을 검사한다** — 화면, 서버, 저장소다.

```
사람이 입력  ──▶  화면이 먼저 거른다      : 고칠 곳을 즉시 알려주려고
                    │
                    ▼
             서버가 경계에서 거른다        : 화면을 거치지 않은 요청도 있으므로
                    │
                    ▼
             저장소가 마지막으로 막는다     : 위 둘을 지나쳐도 잘못된 값이 남지 않게
```

같은 것을 세 번 검사하는 것이 낭비로 보이지만, 각 층이 막는 것이 다르다. 화면만 있으면 서버를 직접 부르는 요청이 통과하고, 서버만 있으면 사람이 저장을 눌러야 잘못을 안다. 저장소의 검사는 앞의 둘에 구멍이 나도 데이터가 망가지지 않게 하는 마지막 줄이다.

**이름이 겹치는 것은 저장소가 마지막에 잡는다.** 두 사람이 같은 이름을 동시에 넣으면 화면과 서버의 검사를 둘 다 통과할 수 있다 — 각자 확인할 때는 아직 없었기 때문이다. 그래서 서버는 저장소가 거절한 것을 받아 사람이 읽을 문장으로 바꿔 돌려준다.

**여닫는 시각과 날짜를 고치는 것은 되지만 지우는 것은 아직 안 된다.** 지우면 이미 잡힌 배정과 예약이 함께 사라지므로, 그때 무엇을 어떻게 할지 정한 뒤에 연다.

## Conclusion

기간의 틀이 정해지면, 상시기간의 예약과 집중기간의 배정 결과는 [스케줄러](../scheduler/README.md)에서 보이고, 집중기간의 배정 자체는 [자동 배정](../auto-assignment/README.md)이 담당한다.
