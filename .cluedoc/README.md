## Abstract

Banblit은 하나의 합주실을 2개 이상 밴드 팀이 함께 사용할 때 발생하는 일정 충돌을 줄이기 위해 만든 서비스입니다. 멤버는 자신이 합주에 참여할 수 없는 시간만 등록하면 되고, 공연 전 집중 합주기간에는 시스템이 그 정보를 모아 팀별 합주 시간을 자동으로 배정합니다. 자동 배정으로 해결되지 않으면 사람이 선택할 수 있는 조율안을 생성하여 권한자의 의사결정을 돕습니다. 이 문서는 v1 기획의 전체 구조이고, 각 기능의 자세한 규칙은 아래 하위 paper에서 다룹니다.

## Introduction

밴드 팀들이 하나의 합주실을 공유할 때 팀 간 시간이 자주 겹칩니다. 특히 한 사람이 2개 이상 팀에 속해 있으면 그 사람의 일정이 한 번 변경되는 것만으로도 관련된 팀 전부의 일정이 연쇄적으로 영향받고, 이를 수동으로 조정하는 작업이 가장 큰 병목이었습니다.

그래서 Banblit은 일정 조정을 자동화하고, 자동으로 해결되지 않는 부분만 사람의 판단으로 전달하기로 했습니다. 첫 사용자는 밴드 "IN SIX STRINGS"이고, 이후 다른 밴드로도 같은 방식으로 확장할 계획입니다.

## Description

Banblit의 기능은 멤버와 팀 정보를 바탕으로 작동합니다. 그 위에서 스케줄러가 일정을 표시하고, 집중기간에는 자동 배정이 일정을 생성하며, 자동 배정이 해결하지 못한 부분은 LLM과 권한을 가진 사람이 함께 해결합니다.

```
[계정과 역할] ──▶ [팀과 포지션] ──┬──▶ [스케줄러] ◀── [합주실과 기간]
      │                         │           ▲
      │                         └──▶ [자동 배정] ──▶ [LLM 도우미]
      │                                 ▲
      │                                 └── [스케줄링 API] (바깥에서 호출하는 endpoint)
      │                                          │
      │                                          ▼
      │                                  [데이터 저장소] (저장된 데이터로 배정을 돌리고 결과를 남긴다)
      │
      ├──────────────▶ [게시판과 공지]
      │
      └──────────────▶ [화면] (위 기능들을 사람이 실제로 쓰는 자리)

  ※ [계정과 역할]에서 뻗는 선은 그림에 그친 것이 아니다.
    서버가 요청마다 누가 보냈는지 확인한 뒤에야 나머지로 넘긴다.
```

### 권한과 소속이 바탕을 이룹니다

사람은 계정으로 로그인하여 팀의 포지션을 맡고, 수행할 수 있는 작업은 권한 항목 19개를 활성화하고 비활성화하는 permission set(권한 집합)으로 결정됩니다. 2계층의 역할(헤드매니저/일반멤버)은 제거했습니다. 권한과 소속은 문서에만 기록된 규칙이 아니라 서버가 각 endpoint마다 검증하여 적용하는 규칙이고, 각 endpoint에 필요한 권한은 [계정과 역할](./accounts-and-roles/README.md)에서 다룹니다.

비밀번호를 잃어버렸거나 계정명을 모를 때는 메일로 복구합니다. 재설정 링크는 1회만 사용할 수 있고 30분 후 만료되며, 비밀번호를 변경하면 그 계정의 모든 로그인이 종료됩니다. 해당 이메일로 가입된 계정이 있는지 여부는 알려주지 않습니다.

### 일정은 보여주고, 만들고, 조정합니다

스케줄러가 팀 일정과 예약, 개인 일정을 한 화면에서 표시합니다. 집중 합주기간에는 자동 배정이 팀별 합주 시간을 생성하는데, 기간마다 정해진 하루 2회의 계산 시각이 되면 사람이 아무 작업도 수행하지 않아도 계산이 자동으로 실행됩니다. 서버와 별도로 동작하는 서비스가 이 작업을 담당합니다. 자동 배정이 해결되지 않으면 LLM이 조율안을 생성하고, 조율안 승인 권한을 가진 사람이 의사결정합니다.

계산이 실행되어 시간표가 실제로 저장되면 그 기간에 배정을 받은 팀의 사람에게 알림이 남습니다. 배정을 받지 못한 팀 사람과 팀에 소속되지 않은 사람에게는 알림이 남지 않습니다. 알림은 달력 화면 오른쪽 목록의 맨 위에 표시되고, 푸시 알림(앱으로 전송되는 알림)은 아직 미구현입니다. 알림이 생성되는 시점은 [자동 배정](./auto-assignment/README.md)에, 화면에서의 위치는 [스케줄러](./scheduler/README.md)에서 확인합니다.

### 나머지는 소통하고, 남기고, 내놓습니다

팀 게시판과 전체 공지가 팀 내부와 외부의 정보를 공유합니다. 게시글에 파일을 첨부할 수 있으며, 파일당 최대 300MB를 수용하고, 허용된 파일 종류만 저장하며 나머지는 거절합니다. 수용된 파일은 서버 디스크에 보존됩니다. 자세한 내용은 [게시판과 공지](./boards/README.md)에서 확인합니다.

데이터 저장소는 위 정보들을 요청과 무관하게 보존하면서 저장 시점에 규칙을 적용합니다. 화면은 이 기능들을 사람이 사용할 수 있는 형태로 제공하고, 아직 구현되지 않은 endpoint가 무엇인지 표시합니다.

이번에 추가된 3가지 기능(게시판 파일 첨부, 화면 내 알림, 메일을 통한 비밀번호 재설정·계정명 찾기)은 서버 테스트 468개와 화면 테스트 202개가 통과했고 타입 검사가 94개 파일에서 정상임을 확인했습니다. 파일 첨부는 추가로 실제 파일을 업로드하고 다시 다운로드하여 한 바이트도 변경되지 않는 것, 허용되지 않은 파일 종류가 거절되는 것, 게시글을 삭제할 때 파일이 함께 삭제되는 것을 확인했습니다.

## Conclusion

Banblit의 핵심은 "멤버는 사용할 수 없는 시간만 등록하고, 나머지는 시스템과 권한자가 해결한다"입니다. 전체 구조를 이해했다면 이 서비스에서 가장 복잡한 2개 부분인 [자동 배정](./auto-assignment/README.md)과 [LLM 도우미](./llm-assistant/README.md)를 먼저 읽기를 권장합니다. 부가 기능(통계, 공연 관리, 멤버 프로필 등)은 v1 이후 단계적으로 확장할 계획입니다.
